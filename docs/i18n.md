## 1. 概述与设计目标

i18n 模块的核心设计目标：**绝不影响站点可用性**。具体体现为：

1. **永不抛错**：翻译键缺失时按用户设置的语言顺序依次回退，再回退到键本身（或原文），任何环节异常都被捕获并记录警告。
2. **逐元素容错**：DOM 翻译对每个元素独立 try/catch，单个元素失败不影响其他元素。
3. **回退链**：`当前语言 → 语言顺序中的后续语言 → 键本身/原文`。
4. **默认简体中文**：未检测到支持的语言或没有任何偏好时保持中文。
5. **静态站点无后端**：全部逻辑在浏览器端完成，语言偏好存于 `localStorage`。

支持语言：简体中文（`zh-CN`，默认）、English（`en-US`）、日本語（`ja-JP`）、Français（`fr-FR`）、Русский（`ru-RU`）与 العربية（`ar`，RTL）。除中文外均为 AI 翻译，可能不完全准确。

**RTL（从右到左）支持**：`ar` 等 RTL 语言会由 i18n 模块在 `<html dir="rtl">` 上应用书写方向，并通过 `css/rtl.css` 镜像 MDUI 与本站的 LTR 硬编码布局（详见 [5.12](#512-isrtllangcode--书写方向管理) 与 [11.2](#112-新增一种语言)）。

## 3. 核心机制

### 3.1 语言顺序与回退

系统维护一个**语言顺序数组**（`languageOrder`）：

- **第一位**是界面显示语言（`currentLang`）；
- **其余语言**在翻译缺失时按顺序依次回退；
- 回退到底仍缺失时，返回**键本身**（`t()`）或**原文**（`tOr()`）。

示例：顺序为 `['zh-CN', 'en-US']`，查找 `common.nav.resourceList`：
1. 先在 `zh-CN` 语言包查找，命中则返回；
2. 未命中则去 `en-US` 查找；
3. 都未命中则返回 `'common.nav.resourceList'`（键本身）。

### 3.2 语言包结构

语言包是**嵌套对象**，叶子节点为字符串：

```js
// js/i18n/zh-CN.js
const zhCN = {
  common: {
    siteName: 'FCL 下载站',
    nav: {
      resourceList: '资源列表',
    },
  },
  // ...
};
export default zhCN;
```

各语言包应保持**相同的键结构**（否则会触发回退）。语言包按页面/用途分顶层命名空间：`common`、`home`、`list`、`detail`、`down`、`about`、`behavior`、`theme`、`rh`、`intro`、`sponsor`、`sponsorRemind`、`notFound`、`language`、`template`、`logger`、`tags`、`mirror`、`detailMessage`。

### 3.3 键路径解析与转义

- 翻译键用**点号分隔**路径，如 `'common.nav.resourceList'`。
- 当**动态键段本身包含点号或反斜杠**（如标签名 `"MC 1.20"`、软件 ID 中的点）时，必须使用 [`escapeKeySegment()`](#53-escapekeysegmentsegment) 转义：

| 原字符 | 转义后 |
| --- | --- |
| `\` | `\\` |
| `.` | `\.` |

示例：翻译标签 `"MC 1.20"` 应使用 `tags.MC 1\.20` 作为键，即代码写成：

```js
tOr(`tags.${escapeKeySegment(name)}`, name);
```

`getNestedValue()` 在解析时按"未被转义的点号"分割路径，并还原转义（`\\` → `\`，`\.` → `.`）。

### 3.4 参数插值

翻译值中的 `{占位符}` 会被替换为参数值，占位符名仅支持 `[\w.]` 字符（字母、数字、下划线、点号）：

```js
// 语言包
hiddenItems: '显示 {count} 个被筛选条件隐藏的项目',

// 调用
t('common.hiddenItems', { count: 3 }); // => '显示 3 个被筛选条件隐藏的项目'
```

占位符名支持**嵌套键引用**（点号形式），例如语言包中引用其他键的值：

```js
// 语言包：{common.nav.sponsorSite} 会被解析为嵌套键
sponsorNotice: '……请考虑{common.nav.sponsorSite}或者帮忙宣传宣传！',
```

参数缺失时占位符**保持原样**输出（不会抛错）。

## 4. 初始化与偏好存储

### 4.1 初始化流程

`js/common.js` 在页面加载时调用 `initI18n()`，且**位于其他共用模块之前**，保证动态渲染也能读取到正确的语言。

`initI18n()` 流程（幂等，重复调用只初始化一次）：

1. `loadLanguageOrder()` 解析语言顺序（见 4.2）；
2. 设置 `currentLang` 为顺序第一位，写入 `<html lang="…">`；
3. 按当前语言是否为 RTL 写入 `<html dir="rtl|ltr">`（`applyDirection()`，见 [5.12](#512-isrtllangcode--书写方向管理)）；
4. 若 `document.readyState === 'loading'`，等待 `DOMContentLoaded` 后执行；否则立即执行；
5. 调用 `applyTranslations()` 对整个文档应用一次翻译。

### 4.2 语言偏好存储

| 存储键 | 格式 | 说明 |
| --- | --- | --- |
| `fdn-language-order` | JSON 数组，如 `["zh-CN","en-US"]` | 当前使用的语言顺序（第一位为界面语言），**优先读取**。 |
| `fdn-language` | 单个语言代码 | **旧版单值偏好**，仅在新键不存在时读取并迁移到新键。 |

读取逻辑（`loadLanguageOrder()`）：

1. 读 `fdn-language-order`，解析为数组后经 [`normalizeLanguageOrder()`](#归一化) 清洗，并把清洗结果**写回**（清除重复/无效项）；
2. 不存在则读旧键 `fdn-language`，转为顺序并迁移；
3. 都没有则按浏览器语言生成默认顺序（见 4.3），并写回。

归一化规则（`normalizeLanguageOrder()`）：只保留支持的语言、按原顺序去重，并把缺失的支持语言**补到末尾**。

### 4.3 浏览器语言检测

`detectBrowserLang()` 读取 `navigator.language`：

- 以 `zh` 开头 → `zh-CN`；
- 以 `en` 开头 → `en-US`；
- 以 `ja` 开头 → `ja-JP`；
- 以 `fr` 开头 → `fr-FR`；
- 以 `ru` 开头 → `ru-RU`；
- 以 `ar` 开头 → `ar`；
- 其他 → `zh-CN`（默认）。

## 5. JS API 参考

模块导出位置：`js/common/i18n.js`。

### 5.1 `t(key, params?, skip?)`

按语言顺序查找翻译并插值；**找不到时返回键本身**。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `key` | `string` | 翻译键，如 `'common.nav.resourceList'`。 |
| `params` | `object` | 可选，占位符替换参数。 |
| `skip` | `Set<string>` | 可选，需要保留原样的占位符名集合（DOM 占位符回插机制内部使用，业务代码一般用不到）。 |

```js
import { t } from '../common/i18n.js';

t('common.nav.resourceList');                  // => '资源列表'
t('common.hiddenItems', { count: 5 });         // => '显示 5 个被筛选条件隐藏的项目'
t('不存在的键');                                // => '不存在的键'
```

### 5.2 `tOr(key, fallback, params?)`

翻译键**存在时返回翻译值，不存在时返回 fallback 原文**。用于数据源中本身就是中文的内容（标签、设置项、线路名等），实现"数据源保持单一语言，未收录的键自动回退原文"。

```js
// 数据源里的标签名 '启动器'，语言包存在 tags.启动器 则用翻译，否则显示原文
tOr(`tags.${escapeKeySegment(name)}`, name);
```

### 5.3 `escapeKeySegment(segment)`

转义动态键段中的点号与反斜杠（见 [3.3](#33-键路径解析与转义)）。**凡是用变量拼接键路径的地方都必须调用它。**

### 5.4 `translateTag(name)`

翻译标签名的便捷封装，等价于 `tOr('tags.<转义后的名称>', name)`：

```js
translateTag('启动器');   // en-US 下 => 'Launchers'
translateTag('未知标签'); // 语言包没有 => '未知标签'
```

### 5.5 `getCurrentLang()` / `getLanguageOrder()` / `getSupportedLanguages()`

```js
getCurrentLang();          // => 'zh-CN' | 'en-US' | 'ja-JP' | 'fr-FR' | 'ru-RU' | 'ar'，当前界面语言
getLanguageOrder();        // => ['zh-CN', 'en-US', 'ar']，返回副本（第一位为界面语言）
getSupportedLanguages();   // => [{ code: 'zh-CN', name: '简体中文' }, { code: 'en-US', name: 'English' }, { code: 'ru-RU', name: 'Русский' }, { code: 'ar', name: 'العربية' }]
```

### 5.6 `setLanguageOrder(order, options?)`

设置语言顺序并保存偏好。

```js
setLanguageOrder(['en-US', 'zh-CN']);                     // 默认 reload=true，保存后刷新页面
setLanguageOrder(['en-US', 'zh-CN'], { reload: false });  // 不刷新（语言设置页排序时用，实时生效）
```

行为：

- 顺序经 `normalizeLanguageOrder()` 清洗后才生效；
- 更新 `currentLang` 为第一位，并写回 `fdn-language-order`、更新 `<html lang>` 与 `<html dir>`（RTL 时置 `rtl`）；
- **当前设计为保存后强制刷新页面**（`applyTranslations` 已注释，属死代码，见 11.4）；
- `reload: false` 时语言设置页可实时预览排序效果，但完整生效仍需刷新。

### 5.7 `applyTranslations(root?)`

对 DOM 应用翻译。默认扫描整个 `document`；传入 `root` 时先处理 root 自身（若带 `data-i18n`），再处理其全部后代。详见 [第 6 章](#6-html-静态文案翻译data-i18n)。

### 5.8 `translateDynamicContent(container)`

翻译动态插入的内容，是 `applyTranslations(container)` 的别名。**凡是用 JS 向 DOM 插入含 `data-i18n` 的 HTML 时，插入后必须调用它**（否则新内容不翻译）。典型场景：抽屉模板加载（`js/common/drawer.js`）。

```js
import { translateDynamicContent } from './i18n.js';

drawer.replaceChildren(template.content);
translateDynamicContent(drawer);   // 对动态内容应用翻译
```

### 5.9 `getLocalizedPath(path)`

生成本地资源的本地化路径；**当前语言为中文或路径不合法时返回 `null`**。

```js
// currentLang === 'en-US' 时：
getLocalizedPath('/data/announcement.html');       // => '/data/announcement.en-US.html'
getLocalizedPath('/data/drawer.html?x=1#top');     // => '/data/drawer.en-US.html?x=1#top'（query/hash 保留）
getLocalizedPath('/data/announcement.html');       // currentLang === 'zh-CN' 时 => null

// 无扩展名或扩展名异常时返回 null，避免调用方重复请求同一 URL：
getLocalizedPath('/data/noext');                   // => null
```

规则：

- 仅对**带扩展名**的本地文件（以 `/` 开头）生成 `.<lang>` 版本；
- 先剥离 query/hash，避免查询参数或锚点里的点被误当成扩展名；
- 中文（`zh-CN`）不生成本地化路径。

配合 `js/http/client.js` 的 `getLocalizedText(url, options)` 使用：优先请求本地化版本，**404/403 时回退原文**；超时/网络错误/用户取消（`abort`）直接抛出，不静默回退。

```js
import { getLocalizedText } from '../http/client.js';

// 英文下优先请求 /data/announcement.en-US.html，404 时回退 /data/announcement.html
const html = await getLocalizedText('/data/announcement.html', { cache: true });
```

### 5.10 `LANGUAGE_PACKS` / `LANGUAGE_NAMES`

```js
LANGUAGE_PACKS;   // { 'zh-CN': zhCN, 'en-US': enUS, 'ja-JP': jaJP, 'fr-FR': frFR, 'ru-RU': ruRU, 'ar': ar }，语言包对象映射（比较表等场景直接读取）
LANGUAGE_NAMES;   // { 'zh-CN': '简体中文', 'en-US': 'English', 'ja-JP': '日本語', 'fr-FR': 'Français', 'ru-RU': 'Русский', 'ar': 'العربية' }，语言显示名称
```

### 5.11 `initI18n()`

初始化 i18n（见 [4.1](#41-初始化流程)）。返回 Promise，幂等。**每页只需在入口调用一次**（`js/common.js` 已调用，业务代码一般无需再调）。

### 5.12 `isRTLLang(code)` 与书写方向管理

```js
isRTLLang('ar');       // => true（阿拉伯语）
isRTLLang('ar-SA');    // => true（带区域代码同样识别）
isRTLLang('he');       // => true（希伯来语）
isRTLLang('zh-CN');    // => false
```

- 按语言主代码（`-` 前的部分）匹配 `RTL_BASE_LANGS`（`ar/he/fa/ur/ps/dv/ku/sd`），**新增 RTL 语言时在此集合登记**；
- `initI18n()` 与 `setLanguageOrder()` 都会调用内部 `applyDirection()`，把 `<html dir>` 设为 `rtl` 或 `ltr`；
- 所有页面 head 中有一个内联脚本（位于 `rtl.css` 链接之后），按已保存的语言偏好**提前**设置 `lang`/`dir`，避免页面加载后布局整体翻转闪烁；该脚本中的 RTL 正则与 `RTL_BASE_LANGS` 保持一致，修改时两处需同步；
- `js/common/drawer.js` 通过 `isRTLLang(getCurrentLang())` 决定抽屉位于左侧（RTL）还是右侧（LTR）——MDUI 的抽屉位置逻辑由 `mdui-drawer-left/right` 类决定；
- 布局镜像样式统一放在 `css/rtl.css`（MDUI 1.0.2 本身不含 RTL 支持）。

## 6. HTML 静态文案翻译（`data-i18n`）

静态 HTML 中的文案通过 `data-i18n` 属性标记，页面加载或内容插入时由 `applyTranslations()` 统一翻译。标记元素在语言包中找不到对应翻译时**保持原文不变**。

### 6.1 基本用法：翻译文本内容

```html
<span data-i18n="common.nav.resourceList">资源列表</span>
```

翻译时元素 `textContent` 会被替换为翻译值。`<title>`、`<meta>` 等 head 中的元素同样支持：

```html
<title data-i18n="language.pageTitle">语言设置 - FCL下载站</title>
```

### 6.2 翻译属性：`data-i18n-attr`

同时声明 `data-i18n`（键）与 `data-i18n-attr`（要翻译的属性名），可翻译 `title`、`alt`、`content` 等属性：

```html
<!-- meta 标签：翻译 content 属性 -->
<meta name="description" data-i18n="language.description" data-i18n-attr="content" content="设置FCL下载站的界面语言与回退顺序。">

<!-- 链接：翻译 title 属性 -->
<a data-i18n="common.nav.statsAlt" data-i18n-attr="title" title="51la网站统计" href="https://v6.51.la/…">
  <img data-i18n="common.nav.statsAlt" data-i18n-attr="alt" alt="51.la 统计" src="…">
</a>
```

注意：**声明了 `data-i18n-attr` 的元素只翻译属性，不翻译文本内容**。

### 6.3 参数替换：`data-i18n-params`

需要插值参数的静态元素，用 `data-i18n-params` 提供 JSON 格式的参数：

```html
<p data-i18n="common.nav.siteRuntime" data-i18n-params='{"runtime":"1小时"}'></p>
```

参数解析失败仅记录警告，元素保持原文。

### 6.4 混合内容占位符（子元素回插）

当翻译文本中需要**嵌入子元素**（链接、高亮、动态数值）时使用占位符机制：

1. 父元素带 `data-i18n`，其**直接子元素**中带 `data-i18n` 的会被当作占位符；
2. 翻译时子元素**临时移出 DOM**，父文本先设置 `textContent`，再把子元素按 `{name}` token 出现的位置**回插**；
3. token 在翻译中缺失时，子元素**追加到元素末尾**兜底（并记录警告），避免链接等子元素被永久丢弃。

两种占位符写法：

```html
<!-- 写法 A：data-i18n="some.key" —— 子元素先翻译（含属性翻译），翻译结果作为 {some.key} 占位 -->
<!-- 真实示例：data/drawer.html 的 statsNotice，<a> 子元素作为 {common.nav.statsAlt} 占位 -->
<p data-i18n="common.nav.statsNotice">此网站使用
  <a data-i18n="common.nav.statsAlt" data-i18n-attr="title">51la网站统计</a>
  统计访问信息，公开的详细报表见下方链接。
</p>
```

```html
<!-- 写法 B：data-i18n="[name]" —— 不翻译子元素，按 {name} 占位（方括号表示"纯占位符"） -->
<!-- 真实示例：data/drawer.html 的 siteRuntime，<span> 由 JS 定时注入运行时长 -->
<p data-i18n="common.nav.siteRuntime">这坨屎山已经非常松弛地运行了
  <span id="drawer-runtime" data-i18n="[runtime]"></span>。
</p>
```

对应语言包（父模板的翻译文本中必须存在对应 token）：

```js
nav: {
  statsNotice: '此网站使用 {common.nav.statsAlt} 统计访问信息，公开的详细报表见下方链接。',
  statsAlt: '51la网站统计',
  siteRuntime: '这坨屎山已经非常松弛地运行了{runtime}。',
},
```

实际例子：`data/drawer.html` 中的运行时间占位符，配合 `js/common/drawer.js` 的 `#drawer-runtime` 定时注入运行时长（见 [6.5](#65-动态插入-html-的翻译)）。

> 同一 token 在翻译中出现多次时，会克隆占位符节点逐个插入。占位符元素必须是父元素的**直接子元素**。

### 6.5 动态插入 HTML 的翻译

用 JS 注入的 HTML（如抽屉模板）需要**在插入后手动调用 `translateDynamicContent()`**：

```js
drawer.replaceChildren(template.content);
translateDynamicContent(drawer);   // 对动态加载的抽屉内容应用 i18n 翻译
```

## 7. JS 动态文案翻译

业务代码中动态生成的文案统一使用 [`t()`](#51-tkey-paramsskip) / [`tOr()`](#52-torkey-fallback-params) / [`translateTag()`](#54-translatetagname)，**不要硬编码中文**。典型场景（均可在 `js/views/`、`js/controllers/` 中找到示例）：

```js
// 普通翻译 + 参数
title.textContent = t('common.nav.bookmarks');
showSnackbar(t('language.saved'));

// 数据源中文内容：键存在则翻译，否则回退原文
p.textContent = tOr(`behavior.setting.${escapeKeySegment(setting.name)}`, setting.name);

// 动态键必须转义
option.textContent = tOr(`behavior.option.${escapeKeySegment(setting.name)}.${escapeKeySegment(opt.value)}`, opt.label);

// 标签翻译
tags.forEach((tag) => fragment.appendChild(createTagButton(translateTag(tag.name), String(tag.id))));

// 消息类型通用化
: tOr(`common.${escapeKeySegment(type)}Message`, type);   // common.errorMessage / common.warningMessage 等
```

**规则：**

- 拼接动态键时**必须**用 `escapeKeySegment()` 转义；
- 从数据源读出的中文（`setting.name`、`tag.name`、`mirror.name`、`detail.json` 的 `message` 等）用 `tOr()`，保证未收录键显示原文而非键名；
- 结构稳定的键（`common.nav.*`、`language.*` 等）用 `t()`。

## 8. 数据源内容翻译约定

数据源（`data/*.json`、`data/*.html`）**保持单一语言（中文）不变**，翻译分三类处理。

### 8.1 短文本：放入语言包按 ID 寻址

短文本（设置项、标签、线路名、详情页消息、贡献者与开源项目描述等）统一放在语言包中，按**稳定 ID/序号**寻址：

| 语言包命名空间 | 键结构 | 数据来源 |
| --- | --- | --- |
| `tags` | `tags.<中文标签名>`（需 `escapeKeySegment`） | `data/tag.json` |
| `mirror` | `mirror.<线路ID>`，如 `mirror.0` | `data/mirror.json` |
| `detailMessage` | `detailMessage.<软件ID>.<序号>`，如 `detailMessage.10.0` | `data/software/*/detail.json` 的 `message` |
| `behavior.setting` / `behavior.option` | `behavior.setting.<设置项名>`、`behavior.option.<设置项名>.<选项值>` | `data/setting.json` |
| `about.contributor` / `about.project` | `about.contributor.<贡献者ID>.<行号>`、`about.project.<序号>.description` 等 | `data/software/contribute.json`、`usedProj.json` |
| `intro.titles` | `intro.titles.<软件ID>.<序号>` | `data/software/*/detail.json` 的文档标题 |

统一使用 `tOr()` 访问：**键存在用翻译，不存在回退原文**。

### 8.2 长文档：按语言后缀存放文件

长文档（公告、软件介绍页）**按语言后缀存放文件**，加载时优先当前语言，缺失时回退中文原文件：

```
data/announcement.html          data/announcement.en-US.html          data/announcement.ru-RU.html          data/announcement.ar.html
data/software/0/intro.html      data/software/0/intro.en-US.html      data/software/0/intro.ru-RU.html      data/software/0/intro.ar.html
```

通过 `js/http/client.js` 的 `getLocalizedText()` 加载（内部使用 `getLocalizedPath()`）：

```js
// 英文下优先 /data/announcement.en-US.html，404/403 回退 /data/announcement.html
const html = await getLocalizedText('/data/announcement.html', { cache: true });
```

**新增语言时，长文档需要按新语言后缀再存一份**（见 [11.2](#112-新增一种语言)）。

### 8.3 HTML 模板：`{{key}}` 占位符替换

`data/sponsorRemind.html` 这类**会被 DOMPurify 净化**的模板无法使用 `data-i18n`（净化会剥离 `data-*` 属性），改用 `{{key}}` 占位符，在净化**之前**由 JS 替换（见 `js/common/sponsorRemind.js`）：

```html
<!-- data/sponsorRemind.html -->
<p>{{sponsorRemind.visitCount}}</p>
```

```js
// js/common/sponsorRemind.js —— 必须在 createSafeContent 净化前完成翻译
const visitCountHtml = t('sponsorRemind.visitCount').replace(/\{count\}/g, '<span id="visitCount"></span>');
const localizedHtml = sponsorHtml
  .replace(/\{\{sponsorRemind\.visitCount\}\}/g, () => visitCountHtml)   // 先替换含 {count} 的特殊项
  .replace(/\{\{([\w.]+)\}\}/g, (match, key) => t(key))                   // 其余通用 {{key}} 替换
  .replace(/\{count\}/g, '');
```

## 9. 日志（logger）的国际化

`js/common/logger.js` 的 context 前缀支持两种形式，经 `translateContext()` 翻译：

1. **静态 context（字符串）**：以中文原文为键，匹配语言包 `logger.context.<原文>`，未收录时原样返回：

```js
logError(error, '公告');      // 匹配 logger.context.公告
logWarn(error, '解析语言顺序偏好');  // 匹配 logger.context.解析语言顺序偏好
```

2. **动态 context（对象）**：含动态变量时使用专用键 + 参数：

```js
logWarn(error, { key: 'logger.context.readPreference', params: { key } });
logWarn(error, { key: 'logger.context.i18nTranslateError', params: { key } });
```

在 `js/i18n/*.js` 的 `logger.context` 命名空间下维护这些键。**新增日志 context 时记得在两个语言包中同步添加。**

## 10. 语言设置页

入口：`html/language.html` + `js/controllers/languageController.js` + `js/views/languageView.js`，导航入口在右侧抽屉"网站设置 → 语言设置"。

### 10.1 语言顺序表格

- 可拖拽表格（拖动手柄或上/下按钮）调整语言顺序；
- **列表顺序即语言优先级**：第一位为界面显示语言，其余为回退顺序；
- 拖拽后调用 `setLanguageOrder(order, { reload: false })` 立即保存并实时生效（防抖 500ms 弹出保存提示）；
- 完整生效需**刷新页面**（`applyTranslations` 已禁用，见 11.4）。

### 10.2 语言比较表

点击"加载语言比较表"后生成：

- 按语言包的键（扁平化）逐行列出所有翻译，每行 key + 各语言翻译输入框；
- 顶部搜索框可按 key 或任一语言翻译内容过滤；
- 语言包中**不存在某键时，该语言输入框为空**（利于发现缺失翻译）。

### 10.3 下载语言包与生成新语言

- 列头下载按钮：从 `LANGUAGE_PACKS` 重建对应语言包的 `.js` 文件并下载；
- 新语言列：填入语言代码（如 `ja-JP`，校验规则 `^[a-zA-Z][a-zA-Z0-9-]*$`）与各键翻译后下载，生成一个可直接放入 `js/i18n/` 的语言包文件；
- 生成的下载文件为 `const <code> = {...}; export default <code>;` 格式。

## 11. 维护指南

### 11.1 新增/修改翻译键

1. 在 `js/i18n/zh-CN.js` 找到对应命名空间添加/修改键（zh-CN 是基准语言）；
2. **同步修改** `js/i18n/en-US.js` 的相同位置；
3. 若新键会被 DOM 元素使用，给元素加 `data-i18n="<键>"`（属性翻译加 `data-i18n-attr`）；
4. 若在 JS 中使用，按 [第 7 章](#7-js-动态文案翻译) 规则调用 `t()` / `tOr()`。

检查清单：

- [ ] zh-CN 与 en-US 键结构保持一致；
- [ ] 含 `{占位符}` 的键，所有语言包占位符一致；
- [ ] 动态键已用 `escapeKeySegment()` 转义；
- [ ] 数据源中文内容用 `tOr()` 而非 `t()`；
- [ ] 新增 logger context 时同步 `logger.context` 下的键。

### 11.2 新增一种语言

以新增 `ja-JP` 为例：

1. **生成语言包文件**：复制 `js/i18n/en-US.js` 为 `js/i18n/ja-JP.js`，替换翻译内容（可直接用语言设置页的比较表 + 新语言列下载生成）；
2. **注册语言包**：在 `js/common/i18n.js` 中导入并加入 `LANGUAGE_PACKS` 与 `LANGUAGE_NAMES`：

```js
import jaJP from '../i18n/ja-JP.js';

export const LANGUAGE_PACKS = {
  'zh-CN': zhCN,
  'en-US': enUS,
  'ja-JP': jaJP,
};

export const LANGUAGE_NAMES = {
  'zh-CN': '简体中文',
  'en-US': 'English',
  'ja-JP': '日本語',
};
```

3. **长文档本地化**：为公告与各软件介绍页添加 `*.ja-JP.html` 副本（`getLocalizedPath` 会自动生成对应路径，404 时回退中文原文件）；
4. **浏览器检测**：`detectBrowserLang()` 目前只识别 `zh*` / `en*` / `ja*` / `fr*` / `ru*` / `ar*`，新语言按需补充（否则该语言用户默认落到中文）；
5. **验证**：打开语言设置页确认新语言出现在列表中，切换后各页面正常翻译。

> 不需要在语言设置页做任何配置，语言列表由 `LANGUAGE_PACKS` 自动生成。

**新增 RTL（从右到左）语言**（如阿拉伯语 `ar`）时，除上述步骤外还需：

1. 在 `js/common/i18n.js` 的 `RTL_BASE_LANGS` 集合中登记语言主代码（`ar/he/fa/ur/ps/dv/ku/sd`），`isRTLLang()` 会自动生效；
2. 检查 `css/rtl.css` 是否覆盖了新语言的布局需求（面板箭头、表格边框、列表间距、抽屉等）；
3. 所有页面 head 内联脚本中的 RTL 正则与 `RTL_BASE_LANGS` 同步（见 [5.12](#512-isrtllangcode--书写方向管理)）；
4. 抽屉位置由 `js/common/drawer.js` 自动镜像，无需额外改动；
5. 语言包翻译完成后，用语言设置页的比较表核对**键与占位符完整性**（RTL 语言尤其注意 `{占位符}` 不被反向标点破坏）。

### 11.3 维护数据源内容

- 修改标签、设置项、线路名等**短文本**：改语言包（`tags` / `behavior.setting` / `mirror` 等命名空间），数据源本身不动；
- 修改公告、介绍文档等**长文档**：更新 `data/announcement.html` 等中文原文件，并**同步所有语言的本地化副本**（缺失副本时该语言用户回退中文）；
- 修改详情页 `message` 字段：数据源 + 语言包 `detailMessage.<ID>.<序号>` 两处同步。

### 11.4 清理死键

- `js/i18n/zh-CN.js` 头部有 `TODO: 清理死键` 标记，语言包中可能存在已不使用的翻译键；
- `js/common/i18n.js` 的 `setLanguageOrder()` 中有一段**已注释的死代码**（`applyTranslations()` + 空 try/catch），当前设计为"保存后强制刷新"，注释的 `applyTranslations` 逻辑已不生效——不要误以为 `setLanguageOrder` 会实时重译 DOM；
- 清理时可用语言设置页的比较表核对键的实际使用情况，或用 `grep` 检索键名在 HTML/JS 中的引用。

## 12. 注意事项与排错

**设计约束**

- **翻译缺失不报错**：`t()` 返回键本身、`tOr()` 返回原文、DOM 元素保持原文，页面功能不受影响；
- **`data-i18n-attr` 与文本互斥**：带 `data-i18n-attr` 的元素只翻译属性，其文本内容不会被翻译；
- **占位符必须直接子元素**：`[name]` / `key` 占位符只处理直接子元素，嵌套层级不生效；
- **占位符 token 缺失会追加到末尾**：翻译文本中忘了写 `{name}` 时，子元素会被追加到元素末尾（有日志警告 `i18nMissingPlaceholder`），功能不丢但布局可能错位；
- **`getLocalizedPath` 只处理带扩展名的 `/` 开头路径**：query/hash 会被剥离后再插入语言后缀；
- **`getLocalizedText` 只对 404/403 回退**：超时、网络错误、用户取消（abort）都会直接抛出，不要期望静默回退；
- **模板净化前翻译**：`createSafeContent`（DOMPurify）会剥离 `data-*` 属性，净化过的模板只能使用 `{{key}}` 占位符方案（如赞助提醒）。

**常见问题**

| 现象 | 可能原因 |
| --- | --- |
| 动态插入的内容没翻译 | 插入后忘了调用 `translateDynamicContent()`。 |
| 翻译显示为键名（如 `common.nav.resourceList`） | 该键在所有语言包中都缺失；或动态键拼接未转义（点号被当成路径分隔符）。 |
| 标签/设置项显示原文中文 | 语言包缺少对应 `tags.X` / `behavior.setting.X` 键，`tOr()` 正常回退——补键即可。 |
| 切换语言后页面没变化 | 切换后需要刷新页面（`setLanguageOrder` 默认会刷新；语言设置页 `reload:false` 只实时改顺序，需手动刷新）。 |
| 英文下公告/介绍还是中文 | 缺少 `*.en-US.html` 本地化副本（404 回退中文属预期行为），或未使用 `getLocalizedText()`。 |
| 子元素被排到文本末尾 | 翻译文本中缺少对应 `{token}` 占位符（`i18nMissingPlaceholder` 警告）。 |
| 新语言在设置页不出现 | 未在 `LANGUAGE_PACKS` / `LANGUAGE_NAMES` 中注册。 |
| RTL 语言下某些组件方向不对 | `css/rtl.css` 未覆盖该组件；或新 RTL 语言主代码未登记进 `RTL_BASE_LANGS` 与各页内联脚本。 |
| RTL 语言下抽屉仍从右侧弹出 | `js/common/drawer.js` 在抽屉创建时读取语言，页面需刷新后生效（语言切换本身会刷新）。 |

**安全检查**

- DOM 翻译使用 `textContent` 赋值，天然转义 HTML；但 `data-i18n-params` 的值来自 HTML 属性，翻译结果最终写入 `textContent` / `setAttribute`，不会执行脚本；
- 公告、介绍页等富文本内容一律经 `createSafeContent`（DOMPurify）净化后再插入 DOM，翻译标记无法存活于净化后的内容，长文档走"按语言后缀存放文件"路线，不要试图往长文档里塞 `data-i18n`。
