# i18n 国际化模块：使用与维护文档

本文档覆盖本站 i18n 模块的完整实现：从设计原则、文件结构、API 用法，到静态页面 / 动态内容 / 数据源三种翻译场景，以及新增文案、新增语言、排查问题的维护指南。

核心代码：

- `js/common/i18n.js` —— i18n 核心模块（语言顺序、回退、DOM 翻译、本地化路径）
- `js/i18n/zh-CN.js` —— 简体中文语言包（默认语言）
- `js/i18n/en-US.js` —— English (US) 语言包
- `js/language.js` —— 语言设置页入口（`html/language.html`）

## 1. 概述与设计原则

模块的首要设计目标是**绝不影响站点可用性**，所有能力都围绕这一点展开：

1. **翻译键缺失时按语言顺序回退**：第一位是界面语言，其后是回退顺序；全部缺失时 `t()` 返回键本身，`tOr()` 返回调用方提供的原文，`translateTag()` 返回原始标签名。
2. **逐元素容错**：`applyTranslations` 对每个 DOM 元素单独 try/catch，单个元素翻译失败只记日志，不影响其他元素和整个页面。
3. **语言顺序持久化**：保存在 localStorage 的 `fdn-language-order`（兼容旧版 `fdn-language`），语言设置页可拖拽排序并实时预览。
4. **默认简体中文**：无任何偏好或浏览器语言不被支持时保持中文。
5. **任何异常都不向上抛**：读取、解析、写入偏好失败均降级处理，只通过 `logWarn` 记录。

翻译采用“静态 HTML 标记 + JS 动态获取”双轨：

- 静态页面（`html/*.html`、`data/drawer.html`）通过 `data-i18n` 系列属性声明翻译点，页面加载时由 `applyTranslations()` 统一处理；
- 运行时动态生成的文案（表格、按钮、状态提示、Toast 等）通过 `t()` / `tOr()` 等函数在 JS 中取词；
- 长文档（公告、软件介绍）不放在语言包里，而是按语言后缀存放独立文件（如 `announcement.en-US.html`），由 `getLocalizedText()` 按需加载并回退。

## 3. 核心机制

### 3.1 语言顺序与回退链

整个模块围绕“语言顺序”而不是“单一语言”工作：

```
语言顺序 = [界面语言, 回退语言1, 回退语言2, ...]
```

查找翻译时按顺序遍历：

1. 在第一个语言包里查找 `key`，找到字符串就返回（插值后）；
2. 找不到则依次到后续语言包查找；
3. 所有语言包都没有时：
   - `t()` 返回键本身（如 `common.nav.resourceList`）；
   - `tOr(key, fallback)` 返回调用方传入的原文（通常是数据源里的中文）；
   - `translateTag(name)` 返回原始标签名。

默认顺序为 `['zh-CN', 'en-US']`；用户可在语言设置页把任意支持的语言排到第一位。

### 3.2 键路径

语言包是嵌套对象，翻译键是点号分隔的路径：

```js
// 语言包结构
const zhCN = {
  common: {
    nav: {
      resourceList: '资源列表',
    },
  },
};

// 对应的键
t('common.nav.resourceList');
```

键路径的分隔符是**未转义的点号**。当动态键段本身包含点号（如标签名 `MC 1.20`）时，必须用 `escapeKeySegment()` 转义，否则会被拆成多级路径。

### 3.3 初始化时序

```
页面加载
  -> common.js 最先 import i18n.js 并调用 initI18n()
       -> 读取 fdn-language-order（失败则读旧键 fdn-language，再失败则按浏览器语言检测）
       -> 规范化顺序并写回存储（顺带清除脏数据）
       -> 设置 currentLang 与 <html lang>
       -> DOM 就绪后执行 applyTranslations(document)
            -> 每个带 data-i18n 的元素独立翻译，互不阻塞
```

`initI18n()` 是幂等的：重复调用返回同一个 Promise。它被放在其他公共模块之前执行，保证后面所有动态渲染都能读到正确的 `currentLang` 和语言顺序。

### 3.4 错误处理策略

- 语言包读取、JSON 解析、DOM 查询、单元素翻译全部包在 try/catch 中；
- 失败一律 `logWarn` / `logError`（控制台 + 可配置 Toast），不向调用方抛异常；
- 偏好存储读写失败时降级为内存默认值，页面照常工作；
- 唯一刻意向外抛错的是 `getLocalizedText()` 中的超时/网络错误（避免吞掉真实故障），以及用户主动取消（abort）。

## 4. API 参考

以下 API 均从 `js/common/i18n.js` 导出（`getLocalizedText` 例外，在 `js/http/client.js` 中）。

### 4.1 `t(key, params?, skip?)` —— 取翻译文本

```js
t('common.retry');                       // '重试'
t('common.http.error', { status: 404, statusText: 'Not Found' }); // 'HTTP 404：Not Found'
t('common.hiddenItems', { count: 3 });   // '显示 3 个被筛选条件隐藏的项目'
```

参数：

- `key`：点号分隔的键路径；
- `params`：可选对象，替换文本中的 `{name}` 占位符；占位符名只支持 `[\w.]+`（字母、数字、下划线、点）；
- `skip`：可选 `Set<string>`，其中的占位符名**不替换**（`applyTranslations` 内部用它保护 DOM 占位符元素，普通业务代码不需要传）。

返回值：翻译后的字符串；全部语言包都缺失时返回 `key` 本身。注意**不会抛错**。

未提供的参数会原样保留，例如 `t('common.sortBy')` 返回 `'按 {text} 排序'`。

### 4.2 `tOr(key, fallback)` —— 有翻译用翻译，无翻译用原文

用于数据源里已有的中文内容（标签、线路名、设置项名等）：

```js
tOr(`mirror.${mirror.id}`, mirror.name);
tOr(`tags.${escapeKeySegment(tagName)}`, tagName);
```

与 `t()` 的区别：找不到键时返回调用方传入的 `fallback`，而不是键名。`tOr` 不做参数插值（内部对翻译值调用 `interpolate(value)` 时不传 params）。

### 4.3 `translateTag(name)` —— 翻译标签名

标签名来自 `data/tag.json`（中文）。它等价于：

```js
tOr(`tags.${escapeKeySegment(name)}`, name);
```

无对应翻译时原样返回标签名。

### 4.4 `escapeKeySegment(segment)` —— 转义动态键段

把键段中的 `\` 转成 `\\`、`.` 转成 `\.`，防止动态内容中的点号被当成路径分隔符：

```js
escapeKeySegment('MC 1.20');  // 'MC 1\\.20'
escapeKeySegment('a.b\\c');   // 'a\\.b\\\\c'
```

配套的内部解析函数 `getNestedValue()` 会反向还原。**所有把外部数据拼进键路径的地方都必须使用它**（标签名、设置项名、选项值等）。

### 4.5 `getCurrentLang()` —— 当前界面语言

```js
getCurrentLang(); // 'zh-CN' | 'en-US'
```

返回语言顺序的第一位。用途举例：

- `js/common/announcement.js`：按语言生成公告已读状态键 `fdn-announcement-${lang}`；
- `js/views/rhView.js`：`new Date(...).toLocaleString(getCurrentLang())` 格式化日期。

### 4.6 `getLanguageOrder()` —— 当前语言顺序

返回数组的**副本**（第一位为界面语言）：

```js
getLanguageOrder(); // ['zh-CN', 'en-US']
```

### 4.7 `setLanguageOrder(order, { reload = true })` —— 设置语言顺序

```js
setLanguageOrder(['en-US', 'zh-CN']);                 // 保存并刷新页面
setLanguageOrder(['en-US', 'zh-CN'], { reload: false }); // 只保存，不刷新
```

行为：

1. 规范化：只保留支持的语言、去重，并把缺失的支持语言补到末尾；
2. 更新内存中的 `languageOrder` 与 `currentLang`；
3. 写入 `fdn-language-order`；
4. 设置 `document.documentElement.lang`；
5. 默认 `window.location.reload()` 使整个页面重新翻译。

语言设置页使用 `{ reload: false }` 保存，Toast 提示用户刷新后完整生效。

### 4.8 `getSupportedLanguages()` —— 支持的语言列表

```js
getSupportedLanguages(); // [{ code: 'zh-CN', name: '简体中文' }, { code: 'en-US', name: 'English' }]
```

名称来自 `LANGUAGE_NAMES`，用于语言选择器/排序列表。

### 4.9 `applyTranslations(root = document)` —— 对 DOM 应用翻译

扫描 `root` 自身（若带 `data-i18n`）及其全部带 `data-i18n` 的后代，逐元素翻译。支持：

- `data-i18n="key"`：翻译文本内容；
- `data-i18n-attr="attr"`：翻译指定属性（`title` / `alt` / `content` / `placeholder` 等）；
- `data-i18n-params`：JSON 参数；
- 直接子元素 `data-i18n` 占位符（详见第 5.4 节）。

每个元素独立容错。该函数由 `initI18n()` 在 DOM 就绪后自动调用，一般不需要业务代码手动调用。

### 4.10 `translateDynamicContent(container)` —— 翻译动态插入的内容

`applyTranslations(container)` 的别名，语义上专门用于“运行时插入的新 DOM”：

```js
const template = document.createElement('template');
template.innerHTML = rawHtml;
drawer.replaceChildren(template.content);
translateDynamicContent(drawer); // 对刚插入的抽屉内容应用翻译
```

抽屉（`js/common/drawer.js`）就是先加载 `/data/drawer.html` 再调用它。

### 4.11 `initI18n()` —— 初始化

```js
import { initI18n } from './common/i18n.js';
initI18n();
```

恢复语言偏好 -> 设置 `<html lang>` -> DOM 就绪后应用全页翻译。幂等，返回 `Promise<void>`。`common.js` 在所有页面最先调用它。

### 4.12 `getLocalizedPath(path)` —— 生成本地化文件路径

```js
getLocalizedPath('/data/announcement.html'); // '/data/announcement.en-US.html'（英文界面时）
getLocalizedPath('https://example.com/a.md'); // null（远程地址）
getLocalizedPath('/data/software/0/intro.html?x=1'); // '/data/software/0/intro.en-US.html?x=1'
```

规则（详见第 8.2 节）：

- 当前语言为 `zh-CN` 时返回 `null`（中文原文件即基准文件，不额外请求）；
- 路径必须是以 `/` 开头的本地路径；
- 必须带扩展名（`/foo`、`/foo.` 返回 `null`）；
- 查询串和锚点会原样保留在结果尾部。

### 4.13 `getLocalizedText(url, options)` —— 加载本地化文本（http/client.js）

```js
import { getLocalizedText } from './http/client.js';

const html = await getLocalizedText('/data/announcement.html', { cache: true });
```

优先请求当前语言的本地化版本；请求失败时按规则回退原文件（详见第 8.3 节）。`options` 与 `getText()` 相同（`signal` / `timeoutMs` / `cache`）。

## 5. 静态页面（HTML）翻译

### 5.1 基本文本

在任意元素上写 `data-i18n`，元素的 **textContent 会被整体替换**：

```html
<h1 data-i18n="detail.title">详情</h1>
<title data-i18n="home.title">FCL下载站</title>
```

注意：`data-i18n` 覆盖的是整个元素的文本。若需要保留内部的链接、图标等子元素，见 5.4 占位符。

### 5.2 属性翻译

配合 `data-i18n-attr` 翻译指定属性，最常见的场景是 `<meta>` 和图片 `alt`：

```html
<meta name="description" data-i18n="detail.description" data-i18n-attr="content" content="...">
<img src="/media/img/WeChatRewardQRCode.webp" alt="微信赞赏码" data-i18n="sponsor.qrAlt" data-i18n-attr="alt">
<input placeholder="显示所有" data-i18n="common.searchPlaceholder" data-i18n-attr="placeholder">
```

处理逻辑：存在 `data-i18n-attr` 时只设置该属性，不动文本内容。

### 5.3 参数占位符 `data-i18n-params`

翻译文本里的 `{name}` 由 `data-i18n-params` 提供（必须是合法 JSON，因此 HTML 属性建议用单引号包裹）：

```html
<p data-i18n="common.hiddenItems" data-i18n-params='{"count": 3}'>显示 3 个被筛选条件隐藏的项目</p>
```

JSON 解析失败时记录警告并当作空参数处理，不会抛错。

### 5.4 混合内容与占位符元素

当翻译文本中需要保留子元素（链接、图标、动态数值）时，把子元素标记为占位符。占位符必须是**父元素的直接子元素**，分两种：

1. `data-i18n="[name]"`：子元素本身不翻译，父模板中用 `{name}` 占位；
2. `data-i18n="some.key"`：子元素需要翻译，此时子元素的翻译键就是占位符名，父模板中用 `{some.key}` 占位。

实际例子（`data/drawer.html`）：

```html
<!-- 类型 1：运行时间由 JS 注入，不翻译 -->
<p data-i18n="common.nav.siteRuntime">这坨屎山已经非常松弛地运行了<span id="drawer-runtime" data-i18n="[runtime]"></span>。</p>

<!-- 类型 2：子元素带自己的翻译键，同时作为父模板占位符 -->
<p data-i18n="common.nav.statsNotice">此网站使用 <a data-i18n="common.nav.statsAlt" data-i18n-attr="title" href="...">51la网站统计</a> 统计访问信息……</p>
```

对应语言包：

```js
siteRuntime: '这坨屎山已经非常松弛地运行了{runtime}。',
statsNotice: '此网站使用 {common.nav.statsAlt} 统计访问信息，公开的详细报表见下方链接。',
```

处理流程：

1. 翻译父元素前，把带 `data-i18n` 的直接子元素从 DOM 中移出（否则会被 `textContent` 覆盖销毁）；
2. 父元素文本设为 `t(key, params, skip)`，`skip` 中包含所有占位符名，因此 `{runtime}` / `{common.nav.statsAlt}` 原样保留；
3. 扫描文本节点，按 `{name}` 出现次数把占位符子元素克隆插回；
4. 若翻译文本里完全没有某个占位符 token，则把子元素追加到父元素末尾，并输出警告 `i18n 翻译缺少占位符 ...`（兜底，不让链接等被永久丢弃）；
5. 子元素随后在 `applyTranslations` 的后代扫描中被单独处理（类型 1 跳过，类型 2 翻译自身属性/文本）。

### 5.5 注意事项

- **占位符必须是直接子元素**；嵌套更深的不算。
- 同名占位符出现多次时，后续位置会克隆第一个节点，不会出现“移动同一节点导致文本错位”。
- 父元素先于后代处理（root 自身 -> querySelectorAll 后代），顺序由 `elements` 数组保证。
- 元素既带 `data-i18n` 又带 `data-i18n-attr` 时只翻译属性。
- 不要在会被 `textContent` 覆盖的地方依赖原有子节点——占位符机制是唯一保子元素的方式。

## 6. 动态内容翻译

### 6.1 JS 中取文案

渲染层、控制器、领域模块统一通过 `t()` / `tOr()` 取词。典型调用点：

- `js/views/rhView.js`（21 处）、`js/views/detailView.js`、`js/views/listView.js`：表格、按钮、状态文案；
- `js/http/client.js`：HTTP 错误提示；
- `js/domain/siteInfo.js`、`js/domain/systemInfo.js`：运行时、系统检测文案；
- `js/adapters/download/*.js`：下载适配器的通用提示。

```js
// 状态行
renderStatus(container, 'loading', { message: t('common.loading') });

// 参数插值
option.textContent = item.name || t('common.selectors.noName');
select.setAttribute('aria-label', t('common.selectors.levelAria', { level: level + 1 }));
```

### 6.2 动态插入 DOM 后翻译

任何“加载 HTML 字符串后插入 DOM”的场景，插入后都要调用 `translateDynamicContent(container)`，否则 `data-i18n` 不会被处理。现有实现：

- `js/common/drawer.js` 加载 `/data/drawer.html` 后调用；
- `initI18n()` 在 DOMContentLoaded 后对整页调用。

用 `textContent` 构建的纯 JS 文案（如 `document.createElement` 后 `textContent = t(...)`）不需要这一步，因为文案在创建时已经取好。

### 6.3 `{{key}}` 模板（赞助提醒特例）

`data/sponsorRemind.html` 使用双花括号占位符，由 `js/common/sponsorRemind.js` 在 **DOMPurify 净化之前**替换：

```html
<p>{{sponsorRemind.visitCount}}</p>
<a id="sponsorRemindCloseBtn">{{sponsorRemind.closeForever}}</a>
```

```js
const localizedHtml = sponsorHtml
  .replace(/\{\{sponsorRemind\.visitCount\}\}/g, () => visitCountHtml) // 先替换含 {count} 的特殊文案
  .replace(/\{\{([\w.]+)\}\}/g, (match, key) => t(key))               // 其余 {{key}} 一律翻译
  .replace(/\{count\}/g, '');
```

不能改用 `data-i18n` 的原因：`createSafeContent` 的净化配置会剥离 `data-*` 属性，DOM 级翻译标记无法存活，所以必须在净化前完成替换。

### 6.4 公告

`js/common/announcement.js` 通过 `getLocalizedText('/data/announcement.html', { cache: true })` 加载公告（英文界面自动请求 `announcement.en-US.html`，404 时回退中文原文件）。已读状态按语言分别记账：

```js
function announcementStorageKey() {
  return `fdn-announcement-${getCurrentLang()}`;
}
```

因此切换语言后，另一种语言的公告不会因为内容不同而被误判为“未读”或“已读”。

## 7. 数据源内容的翻译约定

数据源（`data/*.json`）本身保持单一语言（中文），需要显示给用户的中文内容按“稳定 ID/序号”放入语言包，JS 通过动态键寻址。这样新增数据条目时不必翻译数据文件，未收录的键自动回退原文。

### 7.1 动态键映射表

| 数据源内容 | 键格式 | 示例 | 调用位置 |
| --- | --- | --- | --- |
| 标签名 | `tags.<转义后的标签名>` | `tags.MCJE相关` | `translateTag()` |
| 线路名 | `mirror.<线路id>` | `mirror.0` | `downloadController`、`aboutView`、`detailView` |
| 详情页消息 | `detailMessage.<软件id>.<序号>` | `detailMessage.10.0` | `downloadController`、`detailView` |
| 介绍文档标题 | `intro.titles.<软件id>.<序号>` | `intro.titles.0.1` | `introView` |
| 行为设置项名 | `behavior.setting.<转义后的设置项名>` | `behavior.setting.图标尺寸（px）` | `behaviorView` |
| 行为设置选项 | `behavior.option.<设置项名>.<转义后的选项值>` | `behavior.option.资源列表页默认打开方式.detail` | `behaviorView` |
| 设置分类/分组 | `behavior.category.<名称>`、`behavior.group.<名称>` | `behavior.group.common` | `behaviorView` |
| 消息类型标题 | `common.<类型>Message` | `common.warningMessage` | `commonView.renderMessages` |

| 关于页项目 | `about.project.<序号>.description / useDescription` | `about.project.0.description` | `aboutView` |

### 7.2 转义示例

凡键段来自外部数据（可能含点号、反斜杠），拼键时必须转义：

```js
// 正确：标签名可能含点号（如 "MC 1.20"）
tOr(`tags.${escapeKeySegment(tag.name)}`, tag.name);

// 错误：直接拼接会把 "MC 1.20" 拆成 tags -> MC 1 -> 20 三级路径
tOr(`tags.${tag.name}`, tag.name);
```

```js
// 行为设置项名（设置项名称同样可能是中文短语，不含点，但统一转义更稳妥）
p.textContent = tOr(`behavior.setting.${escapeKeySegment(setting.name)}`, setting.name);
```

### 7.3 语言包内数据段的维护

语言包中对应的段落按同样的 ID 结构维护：

```js
// zh-CN.js
mirror: {
  0: '线路1',
  4: '线路5',

  10: {
    0: '已停止更新，建议转到新项目：Fold Craft Launcher。',
```

## 8. 长文档本地化（文件级）

### 8.1 命名规则

本地化文件与原文同目录，文件名在扩展名前插入当前语言代码：

```
data/announcement.html        -> data/announcement.en-US.html
data/software/0/intro.html    -> data/software/0/intro.en-US.html
```

现有本地化文件：

- `data/announcement.en-US.html`
- `data/software/0/intro.en-US.html`

### 8.2 `getLocalizedPath` 规则明细

输入 `/data/announcement.html`，当前语言 `en-US`：

| 输入 | 输出 | 说明 |
| --- | --- | --- |
| `/data/announcement.html` | `/data/announcement.en-US.html` | 常规情况 |
| `/data/announcement.html?ver=1#top` | `/data/announcement.en-US.html?ver=1#top` | query/hash 保留 |
| `/dir/noext` | `null` | 无扩展名，避免重复请求同一 URL |
| `/dir/trail.` | `null` | 扩展名为空 |
| `https://example.com/a.md` | `null` | 非本地路径，远程文档保持原文 |
| 当前语言为 `zh-CN` | `null` | 中文即基准语言，不请求额外文件 |

### 8.3 `getLocalizedText` 回退矩阵

```
请求本地化文件（如 announcement.en-US.html）
  -> 成功          -> 返回本地化内容
  -> HTTP 404/403  -> 回退请求原文件
  -> 用户取消 abort -> 继续向上抛（绝不静默回退）
  -> 超时/网络/解析错误 -> 继续向上抛（避免先白等一次完整超时再重试）
```

没有本地化路径时（中文界面、远程 URL、无扩展名）直接请求原文件，不产生额外请求。

### 8.4 使用位置

- `js/common/announcement.js`：`/data/announcement.html`，带 `cache: true`；
- `js/controllers/introController.js`：介绍文档 `url + file` 拼接后的本地路径，`timeoutMs: 20000`，远程 README（`https://...`）不受影响，保持原文；
- 下载线路描述等其他远程内容不走本地化路径。

## 9. 语言偏好与设置页

### 9.1 存储键

| 键 | 格式 | 说明 |
| --- | --- | --- |
| `fdn-language-order` | JSON 数组，如 `["en-US","zh-CN"]` | 当前主存储；第一位为界面语言 |
| `fdn-language` | 语言代码，如 `"en-US"` | 旧版单值偏好，仅作为迁移来源 |
| `fdn-announcement-<lang>` | 公告内容哈希 | 公告已读状态，按语言分开 |

读取顺序：`fdn-language-order` -> 旧版 `fdn-language` -> 浏览器语言检测（`zh*` -> `zh-CN`，`en*` -> `en-US`，其余默认 `zh-CN`）。每次加载都会把规范化后的顺序写回，自动清理重复项和无效语言。

### 9.2 切换语言流程

1. 用户在 `html/language.html` 拖拽/点按钮调整顺序；
2. 排序组件回调 `setLanguageOrder(codes, { reload: false })`；
3. 偏好立即写入 `fdn-language-order`，Toast 提示“已保存，刷新页面后完整生效”；
4. 用户刷新后 `initI18n()` 按新顺序初始化并翻译整页。

`setLanguageOrder` 的默认行为是保存后直接 `location.reload()`（供将来其他调用方使用）；语言设置页特意传 `reload: false`，避免拖拽过程中反复刷新。

### 9.3 设置页交互

- 列表顺序即优先级，`createSortableTable` 组件负责拖拽排序（桌面用 HTML5 拖拽，触屏/手写笔用手柄拖拽），表格基于 MDUI `.mdui-table` 样式打补丁，含“语言”“代码”“当前”“操作”表头；
- 每行提供上移/下移按钮（`sortable.move`）作为拖拽之外的备选排序方式；
- 第一行标记“当前”徽标；
- 保存 Toast 有 500ms 防抖，连续拖动只提示一次；
- 页面上有提示：除简体中文外的语言均为 AI 翻译，可能不完全准确。

## 10. 维护指南

### 10.1 日常流程总览


### 10.2 新增/修改一条文案

4. 检查：

2. 在 `js/common/i18n.js` 注册：

```js
import jaJP from '../i18n/ja-JP.js';

const LANGUAGE_PACKS = {
  'zh-CN': zhCN,
  'en-US': enUS,
  'ja-JP': jaJP,
};

  'zh-CN': '简体中文',

```

3. 扩展浏览器语言检测（`detectBrowserLang`），把 `ja*` 映射到 `ja-JP`（不改则默认回退中文，也不算错）；
4. 按需提供文件级本地化：`data/announcement.ja-JP.html`、`data/software/0/intro.ja-JP.html`；
5. 跑键对齐检查（见 10.5），确保键集合与 `zh-CN` 完全一致；
6. 验证：
   - 语言设置页出现新语言；
   - 排到第一位后整页翻译；

   - `language.warning` 文案建议同步说明“该语言为 AI 翻译”。

### 10.4 新增本地化长文档

1. 复制原文件为 `原文件名.<语言代码>.html`（如 `intro.ja-JP.html`）；
2. 保持与原文件相同的相对路径目录；
3. 翻译内容；
4. 不需要改任何代码——`getLocalizedPath` 按当前语言自动拼路径，`getLocalizedText` 负责 404 回退；
5. 验证：英文界面能看到英文文档，删除该文件后自动回到中文文档，且控制台无异常。

### 10.5 键对齐检查

两个语言包的**键集合必须完全一致**。可以用下面的脚本快速校验（解析缩进结构，忽略注释与空行）：

```python
import re
from pathlib import Path

def key_paths(path):
    keys, stack = [], []
    for raw in Path(path).read_text(encoding='utf-8').splitlines():
        m = re.match(r'^(\s*)(?:[\'"]?([^\'":\s]+)[\'"]?)\s*:', raw)
        if not m or m.group(2) in ('const', 'export', 'default'):
            continue
        depth = len(m.group(1)) // 2
        stack = stack[:depth] + [m.group(2)]
        keys.append('.'.join(stack))
    return set(keys)

zh = key_paths('js/i18n/zh-CN.js')
en = key_paths('js/i18n/en-US.js')
print('仅 zh-CN 有:', sorted(zh - en))
print('仅 en-US 有:', sorted(en - zh))
print('键总数:', len(zh), len(en))
```

当前状态：zh-CN 与 en-US 各 483 个键，完全对齐。新增语言后也应保持这一状态。

### 10.6 清理死键

`js/i18n/zh-CN.js` 顶部有 `TODO: 清理死键`，说明语言包内存在历史遗留、不再被引用的键。清理方法：

1. 全库搜索键名：`rg -n "common\.xxx|xxx" js html data`；
2. 确认没有 `t()`、`tOr()`、`data-i18n`、`{{key}}` 模板引用；
3. 同时从 `zh-CN.js` 与 `en-US.js` 删除（保持对齐）；
4. 跑键对齐检查并人工抽查页面。

注意：动态键（`mirror.*`、`detailMessage.*`、`tags.*` 等）可能没有字面量引用，删除前需确认对应数据源条目也不存在。

### 10.7 常见问题排查

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 页面上出现 `common.nav.xxx` 这类键名原文 | 键缺失或拼写错误 | 确认两个语言包都加了该键；`t()` 缺键会返回键名本身 |
| 英文界面显示中文 | 该键在 en-US 缺失，按回退顺序回退到了 zh-CN | 补 en-US 翻译；这是设计行为 |
| 数据源内容始终是中文 | `tOr` 找不到动态键，回退原文 | 检查动态键拼法与转义（如 `tags.MC\\.1.20`） |
| `{count}` 之类占位符没被替换 | 未传 params、params JSON 解析失败、或占位符名不在 `[\w.]+` 范围 | 检查 `data-i18n-params` 是否为合法 JSON；JS 调用是否传了对应参数 |
| 翻译后子元素（链接/图标）消失或跑到末尾 | 翻译文本缺少对应 `{token}` | 让翻译包含占位符 token；控制台会有 `i18n 翻译缺少占位符` 警告 |
| 动态插入的 HTML 没翻译 | 插入后未调用 `translateDynamicContent` | 参照 drawer.js：插入后调用一次 |
| 本地化文件不生效 | 文件名/目录不对、无扩展名、中文界面、或路径不以 `/` 开头 | 按 8.2 规则核对路径；确认存在 `<语言码>` 文件 |
| 本地化文件加载很慢/报错 | `getLocalizedText` 对超时/网络错误不回退（设计如此） | 检查文件是否真的存在；404/403 才会静默回退 |
| 切换语言后页面没变化 | 设置页 `reload: false`，需手动刷新 | 刷新页面；或调用 `setLanguageOrder(..., { reload: true })` |
| 控制台有 `解析 i18n 参数失败` | `data-i18n-params` 不是合法 JSON | 修正属性值为 JSON（双引号字符串） |
| 控制台有 `应用翻译失败: <key>` | 该元素翻译时抛异常（参数、占位符等） | 按警告定位元素与键，逐个修复 |
| 公告在切换语言后重新显示 NEW | 已读状态按语言分开存储 | 属设计行为，不是 Bug |
