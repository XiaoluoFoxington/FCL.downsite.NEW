# 提交信息风格（git commit）

> 来自 `GLOBAL_AGENTS.md` 第 7 节。
>
> 由 `FCL.downsite.NEW` 全量 626 条历史归纳（591 条非合并提交中，566 条带「呜」结尾）。  
> **这是用户的口味，不是可以商量的规范**——帮他写提交信息时照做，不要「顺手改成 Conventional Commits」。

## 7. 提交信息风格（git commit）

### 7.1 骨架：全角冒号逐级下钻

```
类型：对象：子对象：具体行为呜~
```

- **一级「类型」**：`新增` / `添加` / `修改` / `修复` / `优化` / `删除` / `移除` / `重构` / `更新` / `移动` / `合并` / `撤销`。  
  高频是 **修改 ＞ 新增 ＞ 修复**。
- **`撤销` = 回滚/退回某个既有提交**，revert 场景专用，不要写成 `修改` / `移除` / `删除`。  
  标题不要有过多描述，直接写上短 hash 就行了。
  例：`[AI] 撤销：3bd6719呜~`
- ⚠️ **`新增` 与 `添加` 不是同义词，别搞混**（这是用户明确纠正过的）：
  - **`新增` = 从无到有开一个新东西**。新资源、新模块、新功能、新文件、新机制。  
    例：`新增：内容：数据源：资源id-16（Acode）呜~`、`新增：GHA：最新版本保留数呜~`、`新增：样式：MDUI主题增强：强调色变量呜~`
  - **`添加` = 往已经存在的东西里再塞一份**。给已有资源加线路/版本/图标，给已有页面加样式，补注释。  
    例：`添加：内容：数据源：资源id-0：线路id-0：1.3.2.5呜~`、`添加：内容：数据源：资源id-15添加自动化呜~`、  
    `添加：内容：数据源：资源ID-12：新增线路ID-1与图标呜~`、`添加：样式：将MDUI主题增强添加到各个页面中呜~`
  - **判别口诀：主体是新的 → `新增`；主体是旧的、只是内容变多了 → `添加`。**
  - 佐证：`资源id-0/3/12` 这些**老资源**几乎一律用 `添加`，而首次出现的资源用 `新增`。
- **二级「对象」**：`功能` / `内容` / `样式` / `数据` / `文档` / `资源` / `工具` / `GHA` / `图标` / `SEO` / `注释` / `a11y`。  
  高频是 **内容 ＞ 功能 ＞ 样式**。
- **三、四级**继续细分到具体模块（`详情页` / `列表页` / `数据源` / `资源id-15` / `千万别点` …）。
- 冒号层级实测分布：3 段 194 条、4 段 224 条、5 段 108 条、6 段 20 条。**3～5 段是常态**，别只写两段。
- 冒号**一律用全角 `：`**（569 条用全角，仅 27 条含半角，那还是英文 `fix:` 之类的残留）。

### 7.2 结尾：几乎必带的语气尾巴

- **绝大多数提交以「呜~」结尾**。变体：`呜~`（主流）、`呜呜~`、`呜！`、`呜。`、`呜……`。
- 这一条**不要省**。它是用户签名式的收尾，缺了读者（也就是用户本人）会觉得不像自己写的。

### 7.3 `&` 表示并列

同一层里有多项时用 `&` 直接拼，**不**写两条也不写成「和」：

```
修改：功能&内容：GHA：神秘PoW呜~
新增：内容：数据源：资源id-12：v1.0.4&v1.0.3呜~
```

### 7.4 正文（body）：第一行是一句人话吐槽

- 标题与正文之间空一行，**正文第一段是写给自己看的心情/吐槽**，与技术无关。这是用户风格的灵魂：  
  「傻子TRAE。」「我没钱充API了……」「嗷呜！不想上学！！！」「这傻逼天气。」「不知不觉依旧5点了（悲」。
- 吐槽常用语气词：`（` 未闭合括号、`（）`、`（？）`、`（悲`、`嗷呜`、`难绷`、`抽象`、`神秘`、`牢`、`（）（）（）`。
- 吐槽可以直接询问用户，也可以自己随便写。
- **但真做了非平凡改动时，吐槽后面会接一段极其严谨的技术正文**——这才是给未来的自己/协作者的。  
- 该详细的场合会详细到引代码符号名、`§` 章节号、条目数量守恒、幂等性论证。**不要吝啬篇幅**。

### 7.5 机改提交的前缀标记

- `[GHA] ` —— GitHub Action 自动提交。格式固定为：  
  `[GHA] 新增：内容：数据源：资源id-<id>：<版本>呜~`  
  或 `[GHA] 修改：内容：更新：<短hash>：verInfo.json与sitemap.xml呜~`  
  正文是整段脚本日志，**不要手工改写**。
- `[AI] ` —— AI 代写的提交，用户会**主动标出来以示区分**（`[AI] ` 后接上面同样的中文骨架）。  
  ⇒ **代理代写提交时，默认加上 `[AI] ` 前缀**，除非用户说不用。
- 用户自己的英文 `feat:` / `fix:` 是**早期或 TRAE 生成**的残留（feat 5 条、fix 13 条），  
  不是现在的风格，别模仿。

### 7.6 其他习惯

- 任务完成后仅提交，不需要推送，推送交给用户手动推。
- 出现在标题里的技术名词直接写原文，**不翻译**：`index.json`、`MDUI`、`PoW`、`i18n`、`nextUrl`、`unset`、`overflow`。  
- 引用提交时用短 hash（`7fee986`），引用 issue 用 `close #9`。

### 7.7 照抄模板

```
<类型>：<对象>：<模块>：<具体行为>呜~

<一句心情吐槽（可选）>

<详细说明改动>
```
