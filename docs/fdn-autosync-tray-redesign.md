# fdn-autosync-tray 重写设计

状态：已批准，已实现第一版。只重写 Windows 本地托盘端；共享同步业务与 GitHub Actions 继续独立运行。

## 运行方式

一个常驻 Windows PowerShell 5.1 进程，用 WinForms `NotifyIcon` 和右键菜单。托盘线程管理菜单、定时和状态；一轮同步在同一进程内的后台 runspace 执行，拿本轮配置副本，返回一次结构化结果。界面不等待网络或 Git；没有常驻 Node、消息协议、任务队列或第二份状态。Node 只在 Sync 阶段按需启动，Git 也只在执行命令时启动。用 Windows 命名互斥体阻止同一仓库重复启动；手动和定时共用一个运行入口，忙时不排队。

目录沿用 `scripts/auto-sync/local/`。启动、菜单和调度放在托盘入口；六阶段编排集中在一个脚本，Windows 专用的 WiFi 和绘图代码按需分开。旧的 Node 常驻壳（`main.mjs`、`modules/`、`PROTOCOL.md`、`settings.ps1`）及其只测旧实现的测试已随本版删除，用户配置、图标和日志保留。启动器无控制台，路径从自身位置解析，支持中文和空格。缺 Node 或 Git 时明确报错；不替用户安装依赖。自启用当前用户 Startup 快捷方式，即登录后启动，不要求管理员权限；搬迁后重建快捷方式。

## 托盘与调度

- 状态区：本次程序启动后完成了几轮、上次完成时间和结果、下次计划时间。第一次完成前不显示上次两行；同步中显示本轮结束后再排程，暂停则显示不安排。计数含失败轮次。
- `立即同步` 在暂停或锁定时仍可用，忙时禁用；`暂停` 只取消自动计划，不中止本轮。每轮结束后等待设置的分钟数；恢复时从现在起算，改间隔后空闲时重排、忙时在本轮结束后用新间隔。睡眠错过多轮也只补一次。
- 锁定时只保留只读状态、立即同步、解锁和浏览日志。解锁用遮盖输入框；未设密码不能锁定。锁定不影响自动运行，重启后保持锁定；它不是 Windows 安全边界。重启和退出先撤销定时，如正在运行则等待本轮收尾；从菜单重启不会额外触发启动同步。
- 配置直接在子菜单里改：勾选项和单选项点选即保存；文字、数字和秘密用单项输入框，图标用文件选择器；取消或保存失败不改变当前配置。浏览只提供配置文件和日志目录。直接编辑 JSON 后重启生效。

| 配置菜单 | 项目 |
| --- | --- |
| 部署 | 开机自启、启动后同步一次、选择图片／重置 |
| 准备 | WiFi 总开关、SSID、密码、优先系统已保存密码、总是尝试连接、失败时跳过整轮 |
| Pull | 跳过、rebase／ff-only |
| Sync | `H1111_SESSION`、`GH_TOKEN` |
| Commit | 跳过、GHA／默认／自定义、自定义用户名和邮箱 |
| Push | 跳过、存在未提交改动时跳过、`PUSH_TOKEN` |
| 结束 | 不论成败断开指定 WiFi、并忘记；标准／累积通知及各自设置 |
| 其他 | 同步间隔（分钟）、日志保留天数、锁定密码 |

## 一轮同步

1. **准备**：检查仓库和目标分支，拒绝未完成的 merge/rebase 等操作。按设置做短时联网检查；需要时按 SSID 连接并核实结果。未启用 WiFi 管理时不切网络。连接失败且配置为跳过时记普通失败，仍收尾；否则记录警告后继续。
2. **Pull**：每轮第一步在任何 Git 写操作或 Sync 前检查整个工作区（暂存、未暂存、未跟踪文件）是否干净；脏则将整轮记为失败、记录具体路径并跳过到结束，不自动 stash、清理、提交或推送。干净后才按所选策略更新明确的上游；冲突停止，不自动选边。禁用 Pull 时后续不会偷偷拉取。无上游或目标不明确时提示，不猜分支。
3. **Sync**：按轮启动 [共享入口](../scripts/auto-sync/sync.mjs)，用现有 `LOCAL_SYNC_STEP_COMMIT=0`、`LOCAL_SYNC_STEP_PUSH=0` 禁用脚本内 Git 写操作，以 `LOCAL_SYNC_RESULT_FILE` 读取本轮独有的临时结果，并结合退出码判断。日志不作为判据。要验证现有结果足以识别可提交的产物；确有缺口才为本地模式增加字段。缺失或坏结果不能报成功；超时与不明异常分别标明。
4. **Commit**：只提交确认由本轮生成或删除的同步数据，绝不把其他暂存内容捎进去。Git 身份只传给本次命令。跳过时产物保留在工作区，本轮不尝试提交。
5. **Push**：Commit 阶段被跳过时 Push 必定随之跳过并直接进入结束阶段。否则，只向核实过的上游推送，不强推、不改 remote。开启「有未提交更改时跳过」时，检查暂存、未暂存和未跟踪文件；关闭时，也只推已存在的提交。推送失败保留本地提交；下一轮即使没有新版，只要起始工作区检查干净仍尝试补推。远端抢先更新时按 Pull 策略处理，无法安全整合则报告，不回滚本地提交。
6. **结束**：始终执行。断开前确认仍连接本轮由工具建立的目标连接，不碰原本已连上的 WiFi，也不碰期间切换过去的网络。「并忘记」仅在成功断开后删除与本轮目标匹配的配置；不能明确识别就不删。清理失败记警告，不覆盖同步主结果。

`成功` 包括同步到新版本或补推成功；只有确实无更新且无待处理项才显示 `已是最新`。网络、远端拒绝及 Git 冲突记 `失败`；程序异常、结果契约不符等记 `内部错误`。有意跳过的阶段写明，尤其不能把未推送写成已发布。

## 本地文件与显示

- 配置、日志、自定义底图在托盘脚本旁。配置 JSON 按要求明文存凭据；临时写入同目录后原子替换，读坏则保留原件并提示，不静默覆盖。迁移时兼容能识别的旧配置字段，不盲目搬旧运行记录。唯一的轻量运行记录只持久化锁定标志和累积通知计数；没有待推队列，Git 提交就是待推记录。
- 配置、凭据备份、临时结果、日志及自定义图标不得入库。凭据只交给需要它的子进程，不进命令行、remote URL、状态、通知或日志。`PUSH_TOKEN` 仅对匹配的 GitHub HTTPS 目标生效，空值沿用系统凭据；无人值守时不弹交互认证。班级电脑上能读明文配置的账户也能读凭据，建议用独立 Windows 账户及最小权限 Token。
- 日志按日记录阶段、耗时和脱敏后的错误；只清理自己的过期日志。写不了日志时给出可见诊断，不把已推送的轮次描述成没推送，也不吞掉原始错误。
- 标准通知按四类独立勾选；成功显示资源数和版本数（纯补推则显示已补推），已是最新显示下次时间，失败和内部错误显示截短、脱敏的摘要。累积模式按 N 轮发一条汇总，内部错误可立即单独通知或仅计入汇总；系统接受汇总后才清零，不把接受等同于用户已看到。
- 默认用你的头像，可选图片复制到本地目录，解码失败保留当前底图。角标占右下角约一半：同步中白色右三角、暂停白色双竖线、成功绿勾、最新绿点、失败及内部错误红叉。按轮廓外扩清出透明描边，不挖方块。同步中优先于暂停，其次才是上次结果；没有结果用原底图。换底图时生成图标变体，状态切换直接复用。

## 验收

先用假同步结果、临时工作仓库和 bare 远端测首次显示、调度互斥、锁定权限、脏工作区、冲突以及「Push 失败后，无新版也能补推」。再在 Windows 实测菜单、休眠、自启、中文路径、角标、通知和 WiFi；不在班级电脑上以未经验证的连接行为试错。现有 [Actions 工作流](../.github/workflows/auto-sync.yml) 不改；若修改共享入口，回归 probe 无候选跳过 sync，以及 sync 原有退出码、Summary、提交和推送行为。本地与 GHA 可以各自运行，但不会共享一把锁；若同时向同一分支写入，只靠 Git 拒绝非快进来防覆盖，建议部署时只保留一个定时写入端。
