# a11y.js 无障碍访问增强脚本深度解析

## 一、整体概述

[a11y.js](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/common/a11y.js) 是一个针对 **MDUI 组件库** 的无障碍访问（Accessibility，简称 a11y）增强脚本。它的核心目标是：**弥补 MDUI 原生组件在屏幕阅读器支持、键盘导航、焦点管理等无障碍特性上的不足，使网站符合 WCAG（Web Content Accessibility Guidelines）标准**。

### 1.1 为什么需要这个脚本？

MDUI 是一个轻量级的 Material Design UI 框架，其组件虽然视觉效果出色，但在无障碍访问方面存在以下缺陷：

| 组件 | MDUI 原生问题 | a11y.js 解决方案 |
|------|-------------|----------------|
| Panel 面板 | 头部不可键盘聚焦、无 ARIA 属性、折叠内容仍可被 Tab 聚焦 | 添加 `role="button"`、`tabindex`、`aria-expanded`、`inert` 属性 |
| Select 选择框 | 生成的 div 不可聚焦、无键盘导航 | 增强为可聚焦按钮、支持方向键/Enter/Esc 操作 |
| Drawer 抽屉 | 打开后焦点不转移、关闭后焦点不恢复、无焦点陷阱 | 完整的焦点生命周期管理 |

### 1.2 脚本架构

脚本采用 **IIFE（立即执行函数表达式）** 模式，整体结构如下：

```
a11y.js
├── 防重复初始化（全局标记）
├── 工具函数（ID生成、可聚焦元素选择器）
├── Panel 面板无障碍增强
│   ├── 状态同步（syncPanelState）
│   ├── 单项初始化（initPanelItem）
│   ├── 批量初始化（initAllPanels）
│   ├── 键盘事件委托（Enter/Space）
│   └── MDUI 事件兜底监听
├── Select 选择框增强
│   ├── 高亮管理
│   ├── 单项增强（enhanceSelect）
│   └── 批量增强（enhanceAllSelects）
├── Drawer 抽屉焦点管理
│   ├── 触发元素记录
│   ├── 打开后自动聚焦
│   ├── 关闭后焦点恢复
│   └── 模态模式键盘交互（Escape + 焦点陷阱）
├── 动态内容处理
│   └── 防抖 MutationObserver
└── 启动引导（bootstrap）
```

## 二、核心模块详解

### 2.1 防重复初始化

```javascript
if (window.__MDUI_PANEL_A11Y_INITED) return;
window.__MDUI_PANEL_A11Y_INITED = true;
```

**作用**：通过全局变量标记脚本是否已初始化，防止重复加载导致的事件绑定叠加、内存泄漏等问题。

**为什么这么做**：
- 该脚本可能在多个页面或多个视图中被重复引入
- 重复绑定事件监听器会导致同一事件触发多次回调
- 使用全局标记是最简单可靠的幂等性保障

### 2.2 Panel（面板）无障碍增强

面板是最常用的折叠/展开组件，也是无障碍问题最集中的地方。

#### 2.2.1 状态同步 — `syncPanelState`

```javascript
function syncPanelState(item) {
  const header = item.querySelector('.mdui-panel-item-header');
  const body = item.querySelector('.mdui-panel-item-body');
  if (!header || !body) return;
  const isOpen = item.classList.contains('mdui-panel-item-open');
  header.setAttribute('aria-expanded', String(isOpen));
  body.toggleAttribute('inert', !isOpen);
}
```

**干了什么**：
- 根据面板是否含有 `mdui-panel-item-open` 类，同步两个 ARIA 状态：
  - `aria-expanded`：告诉屏幕阅读器面板是展开还是折叠
  - `inert`：使折叠状态的面板内容完全不可交互（包括 Tab 聚焦、屏幕阅读器读取）

**为什么这么做**：
- **`aria-expanded`** 是 WAI-ARIA 规范中可折叠控件的标准属性，屏幕阅读器（如 NVDA、VoiceOver）会读取该属性告知用户当前状态
- **`inert` 属性** 是关键：MDUI 折叠面板只是用 CSS 隐藏了内容，但 DOM 仍然存在，用户用 Tab 键仍然可以聚焦到折叠面板内的链接和按钮。`inert` 属性会让该元素及其所有后代完全从可聚焦序列和无障碍树中移除，符合"看不见的东西也不应该被 Tab 到"的无障碍原则

#### 2.2.2 单项初始化 — `initPanelItem`

```javascript
function initPanelItem(item) {
  const header = item.querySelector('.mdui-panel-item-header');
  const body = item.querySelector('.mdui-panel-item-body');
  if (!header || !body) return;

  if (!body.id) body.id = generateId();

  header.setAttribute('role', 'button');
  header.setAttribute('tabindex', '0');
  header.setAttribute('aria-controls', body.id);

  syncPanelState(item);

  new MutationObserver(() => syncPanelState(item)).observe(item, {
    attributes: true,
    attributeFilter: ['class']
  });

  item.dataset.a11yInited = 'true';
}
```

**干了什么**：

| 操作 | 目的 |
|------|------|
| 为 body 生成唯一 ID | 供 `aria-controls` 引用，建立 header 和 body 的关联 |
| `role="button"` | 告诉屏幕阅读器这个 div 是一个按钮（因为 header 本身是 div，不是原生 button） |
| `tabindex="0"` | 使 header 可以通过 Tab 键聚焦 |
| `aria-controls` | 声明该按钮控制哪个元素的展开/折叠 |
| MutationObserver 监听 class | 当 MDUI 通过切换 class 来展开/折叠面板时，自动同步 ARIA 状态 |
| `data-a11y-inited` 标记 | 防止重复初始化同一个面板项 |

**为什么这么做**：
- MDUI 的面板头部是纯 `<div>`，默认不可聚焦，也没有语义。添加 `role="button"` 和 `tabindex="0"` 后，屏幕阅读器会将其识别为可交互的按钮
- **MutationObserver 监听 class 变化**：MDUI 面板的展开/折叠是通过添加/移除 `mdui-panel-item-open` 类实现的。使用 MutationObserver 而不是监听点击事件，是因为面板的展开/折叠可能由多种方式触发（点击、API 调用、其他联动逻辑），监听 class 变化是最可靠的方式
- `aria-controls` + ID 关联：这是 WAI-ARIA 的标准模式，让屏幕阅读器用户知道按钮控制的目标区域

#### 2.2.3 键盘事件委托（Enter / Space）

```javascript
document.addEventListener('keydown', function (e) {
  if (e.key !== 'Enter' && e.key !== ' ') return;

  const target = e.target;
  if (!target.matches('.mdui-panel-item-header[role="button"]')) return;

  e.preventDefault();

  const panelItem = target.closest('.mdui-panel-item');
  if (!panelItem) return;

  const wasClosed = !panelItem.classList.contains('mdui-panel-item-open');

  target.click();

  if (wasClosed) {
    setTimeout(() => {
      if (!panelItem.classList.contains('mdui-panel-item-open')) return;
      const body = panelItem.querySelector('.mdui-panel-item-body');
      if (!body) return;
      const focusable = body.querySelector(FOCUSABLE_SELECTOR);
      if (focusable) {
        focusable.focus();
      } else {
        if (!body.hasAttribute('tabindex')) body.setAttribute('tabindex', '-1');
        body.focus();
      }
    }, 100);
  }
});
```

**干了什么**：
- 在 document 级别监听键盘事件（事件委托）
- 当焦点在面板头部时，按 Enter 或 Space 触发点击（切换展开/折叠）
- 如果是从折叠到展开，延迟 100ms 后将焦点移动到面板内容区域的第一个可聚焦元素；如果没有可聚焦元素，则聚焦到 body 本身

**为什么这么做**：
- **事件委托**：面板可能是动态生成的，在 document 上监听比逐个绑定更高效，也能自动处理新增元素
- **Enter/Space 触发**：原生按钮默认支持 Enter 和 Space 触发点击，但 div + `role="button"` 不会自动获得这个行为，需要手动实现。这是 WAI-ARIA 按钮角色的标准键盘交互要求
- **焦点移入内容区**：这是一个重要的用户体验优化。键盘用户展开面板后，最自然的操作就是继续浏览内容。如果焦点还停留在面板头部，用户需要按很多次 Tab 才能进入内容。自动将焦点移入内容区符合"操作后焦点跟进"的无障碍设计原则
- **setTimeout 100ms**：需要等待 MDUI 的展开动画完成、内容渲染完毕后才能聚焦，否则可能找不到元素或者聚焦失败
- **`tabindex="-1"` + 聚焦 body**：如果面板内没有可聚焦元素（比如只有纯文本），给 body 设置 `tabindex="-1"` 可以让它被程序化聚焦（但不会出现在 Tab 序列中），这样屏幕阅读器会开始读取面板内容

#### 2.2.4 MDUI 事件兜底

```javascript
document.addEventListener('opened.mdui.panel', e => syncPanelState(e.target), true);
document.addEventListener('closed.mdui.panel', e => syncPanelState(e.target), true);
```

**干了什么**：监听 MDUI 面板的自定义事件，作为 MutationObserver 的兜底，确保状态同步。

**为什么需要兜底**：
- 虽然 MutationObserver 已经能监听到 class 变化，但在某些极端情况下（如 MDUI 内部实现变更、或某些浏览器的 MutationObserver 延迟），状态同步可能不及时
- 使用 MDUI 官方提供的事件是最直接的方式，双保险机制确保万无一失
- 使用捕获阶段（`true`）可以在事件冒泡到其他处理器之前就完成同步

### 2.3 Select（选择框）无障碍增强

MDUI 的 Select 组件会把原生 `<select>` 隐藏，生成一个 `<div>` 来模拟选择框。这个 div 默认完全没有无障碍支持。

#### 2.3.1 核心增强 — `enhanceSelect`

```javascript
function enhanceSelect(selectDiv) {
  if (selectDiv.dataset.a11ySelectEnhanced) return;
  selectDiv.dataset.a11ySelectEnhanced = 'true';

  selectDiv.setAttribute('tabindex', '0');
  selectDiv.setAttribute('role', 'button');
  selectDiv.setAttribute('aria-haspopup', 'listbox');

  const nativeSelect = selectDiv.previousElementSibling;
  if (nativeSelect?.tagName === 'SELECT') {
    const label = nativeSelect.getAttribute('aria-label');
    if (label) selectDiv.setAttribute('aria-label', label);
  }
  // ... 键盘交互逻辑
}
```

**干了什么**：

| 属性 | 作用 |
|------|------|
| `tabindex="0"` | 使选择框 div 可被 Tab 聚焦 |
| `role="button"` | 标识为按钮（触发弹出菜单） |
| `aria-haspopup="listbox"` | 告诉屏幕阅读器点击后会弹出一个列表框 |
| 复用 `aria-label` | 从原生 select 继承无障碍标签 |

**为什么这么做**：
- MDUI 的 select 结构是：原生 `<select>` + 模拟的 `<div class="mdui-select">`。原生 select 被隐藏了，但模拟的 div 没有任何无障碍属性
- **复用 `aria-label`**：开发者通常会给原生 select 加 `aria-label`，但不会想到给生成的 div 加。自动继承可以减少开发者的额外工作量

#### 2.3.2 键盘导航

Select 组件支持完整的键盘操作：

| 按键 | 关闭状态 | 打开状态 |
|------|---------|---------|
| Enter / Space | 打开菜单 | 选中高亮项 |
| ArrowDown | 打开菜单，高亮首项 | 下移高亮（循环） |
| ArrowUp | 打开菜单，高亮末项 | 上移高亮（循环） |
| Home | - | 跳到首项 |
| End | - | 跳到末项 |
| Escape | - | 关闭菜单 |

**关键设计考量**：

1. **高亮状态独立管理**：脚本使用 `highlightedIndex` 变量和 `xf-select-highlighted` CSS 类自己管理高亮，而不是依赖 MDUI 内部状态。这样可以确保键盘导航的高亮行为完全可控。

2. **菜单打开时的轮询等待**：
   ```javascript
   if (!items.length) {
     let attempts = 0;
     const direction = key;
     (function waitAndHighlight() {
       const current = getSelectMenuItems(selectDiv);
       if (current.length) {
         highlightedIndex = direction === 'ArrowDown' ? 0 : current.length - 1;
         setSelectHighlight(current, highlightedIndex);
         return;
       }
       if (++attempts < 30) requestAnimationFrame(waitAndHighlight);
     })();
     return;
   }
   ```
   MDUI 的菜单项可能是动态渲染的，刚打开菜单时选项可能还没插入 DOM。使用 `requestAnimationFrame` 轮询最多 30 帧（约 0.5 秒），等待选项渲染完成后再设置初始高亮。

3. **循环导航**：用取模运算 `(highlightedIndex + delta + items.length) % items.length` 实现首尾相连的循环，这是列表框组件的标准键盘行为。

4. **`scrollIntoView` 确保可见**：
   ```javascript
   if (highlighted) highlighted.scrollIntoView({ block: 'nearest', inline: 'nearest' });
   ```
   当选项很多、需要滚动时，确保当前高亮项始终在可视区域内。

### 2.4 Drawer（抽屉）焦点管理

抽屉是一个侧边栏组件，在移动端以模态方式弹出（带遮罩层），在桌面端可能是持久化的。

#### 2.4.1 焦点生命周期管理

```javascript
// 1. 打开前记录触发元素
document.addEventListener('open.mdui.drawer', function () {
  drawerTrigger = document.activeElement;
}, true);

// 2. 打开后聚焦到抽屉内
document.addEventListener('opened.mdui.drawer', function (e) {
  const drawer = e.target;
  const focusable = drawer.querySelectorAll(FOCUSABLE_SELECTOR);
  if (focusable.length) {
    focusable[0].focus();
  } else {
    if (!drawer.hasAttribute('tabindex')) drawer.setAttribute('tabindex', '-1');
    drawer.focus();
  }
}, true);

// 3. 关闭后焦点返回触发元素
document.addEventListener('closed.mdui.drawer', function () {
  if (drawerTrigger && typeof drawerTrigger.focus === 'function') {
    drawerTrigger.focus();
  }
  drawerTrigger = null;
}, true);
```

**干了什么**：实现了完整的模态组件焦点生命周期：
1. **打开前**：记录当前焦点元素（即触发抽屉打开的按钮）
2. **打开后**：将焦点自动移入抽屉内的第一个可聚焦元素
3. **关闭后**：将焦点返回到触发元素

**为什么这么做**：
- 这是 WAI-ARIA 模态对话框（Modal Dialog）模式的标准要求
- **焦点移入**：确保键盘用户和屏幕阅读器用户的注意力立即转移到新打开的内容上
- **焦点恢复**：关闭抽屉后，用户应该回到他们之前所在的位置，而不是焦点丢失在页面顶部或其他随机位置。这对于键盘导航的连贯性至关重要

#### 2.4.2 模态模式键盘交互

```javascript
document.addEventListener('keydown', function (e) {
  const openDrawer = document.querySelector('.mdui-drawer.mdui-drawer-open');
  if (!openDrawer) return;
  if (!document.querySelector('.mdui-overlay.mdui-overlay-show')) return;

  // Escape 关闭抽屉
  if (e.key === 'Escape') {
    e.preventDefault();
    const overlay = document.querySelector('.mdui-overlay.mdui-overlay-show');
    if (overlay) overlay.click();
    return;
  }

  // Tab 焦点陷阱
  if (e.key !== 'Tab') return;
  const focusable = Array.from(openDrawer.querySelectorAll(FOCUSABLE_SELECTOR));
  if (focusable.length < 2) return;

  const first = focusable[0];
  const last = focusable[focusable.length - 1];

  if (e.shiftKey && document.activeElement === first) {
    e.preventDefault();
    last.focus();
  } else if (!e.shiftKey && document.activeElement === last) {
    e.preventDefault();
    first.focus();
  }
});
```

**干了什么**：
- **Escape 关闭**：按 Escape 键关闭抽屉（通过点击遮罩层触发 MDUI 的关闭逻辑）
- **Tab 焦点陷阱（Focus Trap）**：当抽屉以模态方式打开时，Tab 和 Shift+Tab 不会将焦点移出抽屉，而是在抽屉内部循环

**关键设计点**：

1. **判断是否为模态模式**：
   ```javascript
   if (!document.querySelector('.mdui-overlay.mdui-overlay-show')) return;
   ```
   MDUI 抽屉在宽屏下可能是"持久模式"（一直显示，没有遮罩），这时不应该拦截键盘操作。只有当遮罩层显示时（模态模式），才启用 Escape 关闭和焦点陷阱。

2. **点击遮罩层关闭**：
   不直接调用 MDUI API，而是模拟点击遮罩层。这样可以确保走 MDUI 完整的关闭流程，包括事件触发、动画等，状态一致性更好。

3. **焦点陷阱的实现原理**：
   - 获取抽屉内所有可聚焦元素
   - 在第一个元素上按 Shift+Tab → 跳到最后一个
   - 在最后一个元素上按 Tab → 跳到第一个
   - 这样无论怎么按 Tab，焦点都不会跑出抽屉

**为什么需要焦点陷阱**：
- 模态对话框的核心原则是"用户必须处理完当前对话才能继续操作"
- 如果没有焦点陷阱，键盘用户按 Tab 可以将焦点移出抽屉，焦点到了后面被遮罩的页面内容上，这会造成严重的困惑
- 屏幕阅读器用户也可能意外导航到背景内容，破坏模态体验

### 2.5 动态内容处理（防抖 MutationObserver）

```javascript
let pendingMutations = [];
let rafId = null;

function processMutations() {
  const addedNodes = new Set();
  for (const mutation of pendingMutations) {
    if (mutation.type === 'childList' && mutation.addedNodes.length) {
      for (const node of mutation.addedNodes) {
        if (node.nodeType === Node.ELEMENT_NODE) addedNodes.add(node);
      }
    }
  }
  pendingMutations = [];
  rafId = null;

  for (const node of addedNodes) {
    if (node.matches?.('.mdui-panel-item:not([data-a11y-inited])')) {
      initPanelItem(node);
    }
    if (node.matches?.('.mdui-panel-item-header, .mdui-panel-item-body')) {
      const panelItem = node.closest('.mdui-panel-item:not([data-a11y-inited])');
      if (panelItem) initPanelItem(panelItem);
    }
    if (node.querySelectorAll) {
      initAllPanels(node);
      enhanceAllSelects(node);
    }
  }
}

new MutationObserver(mutations => {
  pendingMutations.push(...mutations);
  if (rafId === null) rafId = requestAnimationFrame(processMutations);
}).observe(document.body, { childList: true, subtree: true });
```

**干了什么**：
- 监听整个 document.body 的 DOM 变化（子节点增减，包括子树）
- 使用 `requestAnimationFrame` 做防抖，将同一帧内的多次变更合并处理
- 对新增的元素进行面板初始化和 Select 增强

**关键设计考量**：

1. **为什么需要监听整个 body**：
   - 网站内容可能通过 AJAX / 视图切换 / 模板渲染等方式动态加载
   - 面板和 Select 可能在页面加载完成后才被插入 DOM
   - 监听整个 body 是最通用的方式，能覆盖所有动态插入的场景

2. **防抖优化**：
   - DOM 变化可能非常频繁（比如一次性插入大量节点）
   - 如果每次 mutation 都立即处理，会造成性能问题
   - 使用 `requestAnimationFrame` 把同一帧内的所有 mutations 合并处理，确保每帧最多处理一次，兼顾响应速度和性能

3. **双重检测机制**：
   - 直接检测新增节点本身是不是面板项（`node.matches?.(...)`）
   - 检测新增节点是不是面板的 header 或 body（因为面板可能先插入空的 item，再异步插入 header 和 body）
   - 对新增节点内部做批量扫描（`initAllPanels(node)`、`enhanceAllSelects(node)`）
   
   这种多层检测确保了无论 DOM 以何种顺序插入，都能正确初始化。

4. **`node.matches?.()` 可选链**：
   - 文本节点（`Node.TEXT_NODE`）没有 `matches` 方法
   - 使用可选链可以避免报错，同时过滤掉非元素节点

### 2.6 启动引导（bootstrap）

```javascript
function bootstrap() {
  initAllPanels(document);
  enhanceAllSelects(document);

  // MDUI 的 select 初始化时机不稳定，轮询增强直到找到
  if (!document.querySelectorAll('div.mdui-select').length) {
    let attempts = 0;
    (function retrySelects() {
      enhanceAllSelects(document);
      if (++attempts < 60 && !document.querySelectorAll('div.mdui-select').length) {
        requestAnimationFrame(retrySelects);
      }
    })();
  }

  new MutationObserver(mutations => {
    pendingMutations.push(...mutations);
    if (rafId === null) rafId = requestAnimationFrame(processMutations);
  }).observe(document.body, { childList: true, subtree: true });
}

if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', bootstrap);
} else {
  setTimeout(bootstrap, 0);
}
```

**干了什么**：
- 页面加载完成后执行首次初始化
- 如果找不到 MDUI Select 组件，轮询等待最多 60 帧（约 1 秒）
- 启动全局 MutationObserver 监听后续动态内容

**为什么这么做**：

1. **DOMContentLoaded 时机**：
   - MDUI 的组件初始化通常在 DOMContentLoaded 事件中进行
   - 必须等 MDUI 初始化完成后，才能找到 `.mdui-select` 等组件并做增强
   - 如果脚本在 DOMContentLoaded 之后才加载，则用 `setTimeout(bootstrap, 0)` 放到任务队列末尾，确保 MDUI 已经初始化

2. **Select 轮询**：
   - MDUI 的初始化时机受 CDN 加载速度、缓存状态、脚本执行顺序等多种因素影响
   - 如果首次执行时 MDUI 还没把原生 select 转换成模拟 div，就找不到目标元素
   - 轮询 60 帧（约 1 秒）作为兜底，确保最终能初始化成功

## 三、关键技术模式总结

### 3.1 渐进式增强（Progressive Enhancement）

脚本的整体设计遵循渐进式增强原则：
- 不修改 MDUI 的核心逻辑和 DOM 结构
- 只在现有组件上"附加"无障碍属性和行为
- 即使脚本加载失败，组件的视觉和基本功能不受影响

### 3.2 事件委托 vs 逐个绑定

| 场景 | 策略 | 原因 |
|------|------|------|
| Panel 键盘操作 | 事件委托（document 上监听） | 面板数量多、可能动态生成 |
| Select 键盘操作 | 逐个绑定 | 每个 select 有自己的状态（highlightedIndex）|
| Drawer 焦点管理 | 全局事件 | 抽屉是单例，全局管理更简单 |

### 3.3 双保险同步机制

面板的状态同步使用了 **MutationObserver + MDUI 自定义事件** 的双保险机制：
- MutationObserver 是基础，监听 class 变化
- MDUI 事件是兜底，确保在特殊情况下也能同步
- 两者都调用同一个 `syncPanelState` 函数，不会产生冲突

### 3.4 可聚焦元素选择器

```javascript
const FOCUSABLE_SELECTOR = 'button:not([disabled]), [href], input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])';
```

这个选择器在多个地方复用（面板焦点转移、抽屉焦点管理、焦点陷阱），定义了"哪些元素可以被 Tab 聚焦"的统一标准。包含：
- 未禁用的按钮、输入框、选择框、文本域
- 有 href 的链接
- 设置了 tabindex（且不是 -1）的元素

## 四、设计哲学与权衡

### 4.1 为什么用原生 JS 而不是框架？

- MDUI 本身是原生 JS 库，不依赖任何框架
- 无障碍增强需要直接操作 DOM 和监听底层事件
- 原生 JS 最通用，不引入额外依赖，体积最小

### 4.2 为什么用 IIFE 而不是 ES Module？

- 脚本需要在页面加载早期执行（在 MDUI 初始化后尽快增强）
- IIFE 可以直接通过 `<script>` 标签引入，无需构建工具
- 闭包避免了全局变量污染

### 4.3 性能权衡

| 设计 | 性能影响 | 权衡理由 |
|------|---------|---------|
| 全局 MutationObserver 监听 body | 低-中 | 覆盖所有动态场景的必要代价，防抖后影响很小 |
| 事件委托在 document 上 | 极低 | 只有键盘事件，且有选择器快速过滤 |
| Select 轮询 60 帧 | 极低 | 只在初始加载时执行一次 |
| MutationObserver 监听每个面板的 class | 低 | 面板数量有限，监听成本可接受 |

## 五、覆盖的无障碍标准

这个脚本主要帮助网站符合以下 WCAG 2.1 成功标准：

| 标准 | 描述 | 对应实现 |
|------|------|---------|
| 2.1.1 键盘 | 所有功能都可通过键盘操作 | Panel/Select/Drawer 的键盘支持 |
| 2.1.2 无键盘陷阱 | 焦点不会被困在某区域 | Drawer 的焦点陷阱（模态模式下是有意设计的） |
| 2.4.3 焦点顺序 | 焦点顺序有意义 | inert 属性确保折叠内容不被聚焦 |
| 2.4.7 可见焦点 | 焦点位置清晰可见 | 确保所有可交互元素可聚焦 |
| 3.2.1 获得焦点 | 聚焦时不改变上下文 | 合理的焦点转移逻辑 |
| 4.1.2 名称、角色、值 | 组件有正确的语义 | ARIA 属性（role、aria-expanded、aria-controls 等） |
