## 一、数据源总览

除软件资源相关数据（`software.json`、`tag.json`、`mirror.json`、各软件 `detail.json`）外，项目还包含以下数据源：

| 数据文件 | 类型 | 用途 | 消费位置 |
|---------|------|------|---------|
| `data/contribute.json` | 静态 JSON | 贡献者信息，包括头像、链接、贡献内容 | 关于页、线路对照表 |
| `data/feedback.json` | 静态 JSON | 反馈渠道列表（问卷、Issue 等） | 右侧抽屉菜单 |
| `data/setting.json` | 静态 JSON | 行为设置项的配置树 | 行为设置页 |
| `data/verInfo.json` | 静态 JSON | 当前网站版本（git commit hash） | 页面右下角水印 |
| `data/announcement.html` | 静态 HTML | 网站公告内容 | 右侧抽屉顶部 |
| `data/usedProj.json` | 静态 JSON | 使用的开源项目清单 | 关于页 |
| `localStorage` | 浏览器存储 | 用户偏好（主题、行为设置等） | 所有页面 |

### 基础设施模块

| 模块 | 位置 | 职责 |
|------|------|------|

| 内容安全 | [js/security/content.js](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/security/content.js) | 远程内容净化、Markdown 解析、URL 重写 |

## 二、贡献者数据（contribute.json）

### 文件位置

[data/contribute.json](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/data/contribute.json)

### 用途

存储网站开发与维护贡献者的信息，在**关于页**展示：
- 贡献者卡片（头像、昵称、用户名）
- 外部链接（GitHub、Bilibili、QQ 等）
- 贡献内容描述
- 自动关联其提供的下载线路

### 数据结构

数组形式，每个元素代表一位贡献者。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `number` | **是** | 贡献者唯一整数 ID，被 `mirror.json` 的 `contributeId` 引用 |
| `accentName` | `string` | **是** | 主名称（昵称），用于面板标题和锚点 |
| `name` | `string` | 否 | 副名称（真实姓名或其他称呼），显示在头像卡片副标题 |
| `avatar` | `string` | 否 | 头像 URL，支持本站相对路径或外部绝对 URL。未设置则显示默认占位图 |
| `link` | `Array<object>` | 否 | 外部链接数组 |
| `link[].name` | `string` | **是** | 链接显示名称 |
| `link[].href` | `string` | **是** | 链接地址 |
| `content` | `Array<string>` | 否 | 贡献描述数组，每项渲染为一个列表项 |

### 示例

```json
[
  {
    "id": 0,
    "accentName": "XiaoluoFoxington",
    "name": "洛狐",
    "avatar": "/media/img/contributeAvatar/XiaoluoFoxington.avif",
    "link": [
      {
        "name": "Github",
        "href": "https://github.com/XiaoluoFoxington"
      },
      {
        "name": "Bilibili",
        "href": "https://space.bilibili.com/1561166904"
      }
    ],
    "content": [
      "网站站长"
    ]
  }
]
```

### 消费逻辑

#### 1. 关于页 - 贡献者列表

在 [aboutController.js](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/controllers/aboutController.js) 中加载：

```javascript
const [mirrors, contributors, usedProjects] = await Promise.all([
  getMirrors(),
  getJSON('/data/contribute.json', { cache: true }),
  getJSON('/data/usedProj.json', { cache: true }),
]);
```

在 [aboutView.js → renderContributors()](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/views/aboutView.js#L63-L167) 中渲染：
- 每位贡献者渲染为一个可折叠面板
- 左侧显示头像卡片 + 链接按钮
- 右侧显示贡献描述列表
- 自动关联并显示该贡献者提供的线路
- 面板标题 ID = `accentName`，用于线路对照表的锚点跳转

#### 2. 关于页 - 线路对照表

在 [aboutView.js → renderDownloadLines()](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/views/aboutView.js#L25-L56) 中：
- 遍历 `mirror.json` 中的所有线路
- 通过 `contributeId` 在 `contribute.json` 中查找贡献者
- 渲染为"线路 - 提供者"表格
- 提供者名称为可点击锚点，跳转到下方对应贡献者面板

### 注意事项

1. **ID 必须唯一**：与软件 ID 类似，贡献者 ID 不能重复
2. **与 mirror.json 关联**：`mirror.json` 的 `contributeId` 字段引用此处的 `id`
3. **锚点跳转依赖**：线路对照表的提供者链接跳转到贡献者面板，依赖 `accentName` 作为锚点 ID
4. **头像路径**：建议放在 `/media/img/contributeAvatar/` 目录下

- 数据加载：[aboutController.js](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/controllers/aboutController.js#L22-L26)

## 三、反馈渠道数据（feedback.json）

### 文件位置

[data/feedback.json](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/data/feedback.json)

### 用途

存储用户反馈渠道列表，在**右侧抽屉菜单**的"建议反馈"面板中展示为外链按钮。

### 数据结构

数组形式，每个元素代表一个反馈渠道。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `string` | **是** | 渠道名称，显示为按钮文字的一部分（"通过 {name}"） |
| `href` | `string` | **是** | 反馈链接地址，必须是安全的 http/https 协议 |

### 示例

```json
[
  {
    "name": "腾讯问卷",
    "href": "https://wj.qq.com/s2/27273825/b7f1/"
  },
  {
    "name": "GithubIssue",
    "href": "https://github.com/XiaoluoFoxington/FCL.downsite.NEW/issues/new"
  }
]
```

### 消费逻辑

在 [drawer.js → loadFeedback()](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/common/drawer.js#L54-L74) 中加载并渲染：

1. **懒加载**：抽屉首次创建后才会请求 `feedback.json`，不影响首屏加载
2. **安全过滤**：通过 [`isSafeNavigationUrl()`](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/security/content.js#L131-L140) 校验 URL 协议，过滤掉 `javascript:` 等危险协议
3. **新窗口打开**：所有反馈链接自动添加 `target="_blank"` 和 `rel="noopener noreferrer"`
4. **状态机**：使用统一的 loading → ready/empty/error 状态机
5. **重试机制**：加载失败时显示重试按钮

### 加载时机

- **宽屏（≥1024px）**：页面加载时立即创建抽屉，随即加载反馈渠道
- **窄屏（<1024px）**：用户首次点击菜单按钮时才创建抽屉并加载

加载后数据随抽屉 DOM 单例常驻，再次打开不会重复请求。

### 注意事项

1. **URL 安全**：虽然有安全过滤，但配置时仍应确保链接是可信的
2. **按钮文字**：渲染格式为"通过 {name}"，命名时应通顺（如"腾讯问卷"→"通过 腾讯问卷"）
3. **首屏性能**：懒加载设计确保不会阻塞页面首屏渲染

### 相关源码

- 加载与渲染：[loadFeedback()](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/common/drawer.js#L54-L74)
- 抽屉创建：[createDrawer()](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/common/drawer.js#L77-L121)

## 四、设置配置树（setting.json）

### 文件位置

[data/setting.json](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/data/setting.json)

### 用途

定义**行为设置页**的完整配置树。设置项的名称、选项、默认值、存储键全部由数据驱动，代码中不含硬编码的业务常量。新增设置项只需修改此文件，无需改 JS 代码。

### 数据结构

三层树形结构：分类（category）→ 分组（group）→ 设置项（setting）。

```
分类（behavior）
└── 分组（common / list）
    └── 设置项（id, name, type, options, storageKey）
```

#### 顶层：分类（Category）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `string` | **是** | 分类标识名（英文） |
| `label` | `string` | **是** | 分类显示名称（中文） |
| `children` | `Array<Group>` | **是** | 分组数组 |

#### 中层：分组（Group）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `string` | **是** | 分组标识名（英文） |
| `label` | `string` | **是** | 分组显示名称（中文） |
| `children` | `Array<Setting>` | **是** | 设置项数组 |

#### 底层：设置项（Setting）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `number` | **是** | 设置项唯一 ID |
| `name` | `string` | **是** | 设置项显示名称 |
| `type` | `string` | **是** | 设置类型，目前支持 `"select"`（下拉选择） |
| `options` | `Array<Option>` | **是** | 选项列表 |
| `storageKey` | `string` | **是** | localStorage 存储键名 |

#### 选项（Option）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `value` | `string` | **是** | 选项值，写入 localStorage 的实际值 |
| `label` | `string` | **是** | 选项显示标签 |
| `default` | `boolean` | 否 | 是否为默认值。同一设置项只应有一个 default |

### 完整示例

```json
[
  {
    "name": "behavior",
    "label": "行为设置",
    "children": [
      {
        "name": "common",
        "label": "通用设置",
        "children": [
          {
            "id": 1,
            "name": "字节数格式化前缀",
            "type": "select",

        "name": "list",
        "label": "资源列表",

          {
            "id": 0,

              { "value": "download", "label": "下载页" },
```

### 消费逻辑

#### 1. 行为设置页

### 扩展：新增设置项的步骤

1. 在 `setting.json` 对应分组的 `children` 中添加新设置项
2. 确保 `storageKey` 唯一且有意义的命名（建议 `fdn-` 前缀）
3. 在业务代码中通过 `readPreference(storageKey)` 读取值
4. 若需要实时生效，在对应页面的入口文件中监听变化

### 注意事项

1. **storageKey 命名**：建议统一使用 `fdn-` 前缀，避免与其他网站冲突
2. **默认值**：每个设置项应至少有一个默认值，否则取首项
3. **值校验**：[behaviorView.js](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/views/behaviorView.js#L25-L27) 会校验保存值是否在 options 中，非法值会被拒绝
4. **类型扩展**：目前仅支持 `select` 类型，新增类型需在 `behaviorView.js` 的 `renderSettingItem()` 中添加分支

## 六、网站公告（announcement.html）

### 文件位置

[data/announcement.html](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/data/announcement.html)

### 用途

网站公告内容，显示在**右侧抽屉菜单的最顶部**。新公告会有"NEW"角标提醒，用户点击展开后标记为已读。

### 数据结构

纯 HTML 文件片段，不需要完整的 HTML 文档结构（无需 `<html>`、`<head>`、`<body>`）。

### 示例

```html
<div class="mdui-typo">
  <p>网站域名由于备案，导致无法访问。目前备案已通过，网站恢复访问，感谢大家的支持！</p>
  <p>网站已第4次重制！如果有建议或发现了BUG，请反馈，我看到后将尽快回复！</p>
  <p>网站仍然处于建设中，经常会有新的内容或功能，建议经常硬刷新以清除缓存。</p>
</div>
```

### 消费逻辑

在 [announcement.js → loadAnnouncement()](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/common/announcement.js#L82-L95) 中加载并渲染：

#### 1. 新公告检测机制

- 对公告内容计算 **64 位简单哈希**（[simpleHash64()](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/common/announcement.js#L16-L25)）
- 与 localStorage 中存储的哈希值（`fdn-announcement`）比较
- 不一致则视为新公告，标题旁显示 "new_releases" 图标
- 用户点击展开面板后，写入新哈希值并移除 NEW 标记（仅触发一次）

#### 2. 渲染流程

1. 显示 loading 状态
2. 请求 `announcement.html` 文本内容
3. 计算哈希并判断是否为新公告
4. 创建面板（标题 + 箭头 + 正文）
5. 公告 HTML 经 `createSafeContent` + DOMPurify 净化后插入，与其他富文本模块保持一致的安全策略
6. 绑定点击事件：首次展开标记为已读

#### 3. 安全说明

与其他远程 Markdown/HTML 内容一致：
- 公告 HTML 通过 `createSafeContent` 处理，经 DOMPurify 净化后插入 DOM
- 移除 `<script>`、`<iframe>` 等危险标签，拒绝 `javascript:` 等协议

2. **新公告提醒**：内容有任何变化都会触发 NEW 标记，包括错别字修正
3. **已读状态**：基于浏览器 localStorage，清除浏览器数据会重置为未读
4. **隐私模式**：隐私浏览模式下 localStorage 不可用，会一直显示 NEW 标记，但不影响功能

## 九、HTTP 请求层（http/client.js）

### 概述

[js/http/client.js](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/http/client.js) 是**所有网络请求的唯一入口**。业务代码不能直接调用 `fetch()`，必须通过此模块的 `getJSON()` 或 `getText()` 函数。

### 统一错误类型：HttpError

所有请求失败都抛出 `HttpError`，通过 `kind` 字段区分错误类型：

| kind | 说明 | 触发条件 |
|------|------|---------|
| `network` | 网络请求失败 | 无网络、DNS 失败等 |
| `http` | HTTP 错误状态 | 响应状态码非 2xx |
| `parse` | 解析失败 | JSON 格式错误、文本读取失败 |
| `timeout` | 请求超时 | 超过 timeoutMs |
| `abort` | 请求被取消 | 用户主动切换线路等 |

controller 层可根据 `error.kind` 展示不同的用户提示。

### API

#### getJSON(url, options)

获取 JSON 数据。

```javascript
import { getJSON } from '../http/client.js';

const data = await getJSON('/data/software.json', { cache: true });
```

#### getText(url, options)

获取纯文本数据（Markdown、HTML 等）。

```javascript
import { getText } from '../http/client.js';

const md = await getText(url, { timeoutMs: 20000 });
```

#### clearResponseCache(url?)

清理页面级请求缓存。

```javascript
clearResponseCache();           // 清空全部缓存
clearResponseCache('/data/software.json');  // 清理指定资源
```

### 选项参数（options）

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `signal` | `AbortSignal` | （无） | 用户取消信号，用于切换线路等场景 |
| `timeoutMs` | `number` | `15000` | 请求超时毫秒数。非正数则不启用超时 |
| `cache` | `boolean` | `false` | 是否启用页面级内存缓存 |

### 核心特性

#### 1. 页面级内存缓存

- 当 `cache: true` 时，同一 URL 的请求在页面生命周期内只发起一次
- 缓存的是 **Promise** 而非解析后的值，确保并发请求也只发一次
- 失败的请求不会被缓存，确保重试能真正重新请求
- 缓存键同时包含响应类型（`json:` 或 `text:`），避免同一 URL 被两种方式解析时混用

#### 2. 超时控制

- 默认 15 秒超时（可配置）
- 通过 `AbortController` 实现超时取消
- 超时错误的 `kind` 为 `"timeout"`（优先级高于 abort）

#### 3. 请求取消

- 支持外部传入 `AbortSignal`（用户切换线路时）
- 内部超时信号与外部取消信号合并
- 保留外部取消原因，方便调用方区分
- 取消错误的 `kind` 为 `"abort"`

#### 4. 统一错误处理

- 所有网络错误统一封装为 `HttpError`
- 携带 `url`、`status`、`cause` 等调试信息
- controller 层可根据 `kind` 友好提示用户

### 请求生命周期

```
调用 getJSON/getText
       │
       ▼
检查缓存（cache: true 时）
       │  命中 → 返回缓存的 Promise
       ▼  未命中
创建请求信号（合并外部 signal + 超时）
       │
       ▼
发起 fetch 请求
       │
       ├─ 响应成功 → 解析 JSON/Text → 返回数据 → 写入缓存（成功时）
       │
       ├─ 响应失败（非 2xx）→ 抛出 HttpError(kind='http')
       │
       ├─ 解析失败 → 抛出 HttpError(kind='parse')
       │
       ├─ 超时 → 取消请求 → 抛出 HttpError(kind='timeout')
       │
       └─ 用户取消 → 抛出 HttpError(kind='abort')
       │
       ▼
清理（清除超时定时器、移除事件监听）
```

## 十、内容安全层（security/content.js）

### 概述

[js/security/content.js](file:///f:/XiaoluoFoxington/Project/FCL.downsite.NEW/js/security/content.js) 是**远程内容的安全边界**。所有来自第三方仓库的 HTML 和 Markdown 必须经过此模块处理后才能插入 DOM。

### 核心功能

1. **Markdown 解析**：使用 Marked 库将 Markdown 转为 HTML
2. **HTML 净化**：使用 DOMPurify 移除危险标签和属性
3. **URL 重写**：将相对链接转为绝对地址，收紧协议白名单
4. **懒加载依赖**：Marked 和 DOMPurify 只在首次需要时加载

### API

#### createSafeContent(rawContent, options)

解析并净化远程正文，返回可安全插入 DOM 的 `DocumentFragment`。

```javascript
import { createSafeContent } from '../security/content.js';

const fragment = await createSafeContent(rawMarkdown, {
  type: 'md',           // 'md' 或 'html'
  baseUrl: baseUrl,     // 相对链接的基准 URL
});
container.appendChild(fragment);
```

#### isSafeNavigationUrl(value, options?)

判断 URL 是否可安全用于导航（`href`、`downloadUrl` 等）。

```javascript
import { isSafeNavigationUrl } from '../security/content.js';

if (isSafeNavigationUrl(url, { allowRelative: false })) {
  // 安全，可用于下载链接
}
```

参数：
- `allowRelative`：是否接受以 `/` 开头的本站相对路径，默认 `true`

### 安全策略

#### 1. 标签黑名单（FORBID_TAGS）

以下标签会被 DOMPurify 完全移除：

- `script` - 脚本
- `style` - 样式表
- `iframe` - 内联框架
- `object` - 插件对象
- `embed` - 嵌入内容
- `link` - 外部资源链接
- `meta` - 元数据
- `base` - 基础 URL
- `form` - 表单

#### 2. 属性黑名单（FORBID_ATTR）

- `srcdoc` - iframe 内联内容

#### 3. 禁用 data-* 属性

`ALLOW_DATA_ATTR: false` - 不保留任何 `data-` 属性，防止通过 dataset 注入。

#### 4. URL 协议白名单

**链接（href）**：
- 允许：`http:`、`https:`、`data:`、`mailto:`、`#`、`//`
- 禁止：`javascript:`、`vbscript:`、`file:` 等

**图片（src）**：
- 允许：`http:`、`https:`、`data:image`
- 禁止：其他所有协议

#### 5. 跨域链接处理

自动为外部链接添加：
- `target="_blank"` - 新窗口打开
- `rel="noopener noreferrer"` - 安全隔离

页内锚点（`#` 开头）保持原行为。

#### 6. 图片懒加载

所有 `<img>` 标签自动添加 `loading="lazy"`。

### 外部依赖懒加载

Marked 和 DOMPurify 通过 CDN 懒加载，有以下特性：

1. **首次使用才加载**：用户不打开介绍文档就不会加载这两个库
2. **SRI 完整性校验**：通过 `integrity` 属性确保 CDN 内容未被篡改
3. **Promise 缓存**：多个面板同时展开也只加载一次
4. **失败重试**：加载失败会清除缓存，用户可以重试

固定版本（与 `usedProj.json` 中一致）：
- Marked 15.0.12
- DOMPurify 3.2.6

### 净化流程

```
原始内容（Markdown 或 HTML）
       │
       ▼
Markdown? → 是 → Marked 解析 → HTML
       │
       ▼
DOMPurify 净化（移除危险标签/属性）
       │
       ▼
URL 重写（补齐相对路径、协议校验、跨域处理、懒加载）
       │
       ▼
DocumentFragment（可安全插入 DOM）
```
